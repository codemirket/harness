# Agent coordination strategy

Decide whether useful independent work justifies coordination. A title, complex-sounding task or extra available slot is not enough. Honor explicit user choices about provider, model, reasoning, workflow and delegation. Pi owns each child’s model/authentication and agent loop. Use Mirket’s optional bounded CLI delegation only when it is loaded and qualified; otherwise keep work with the lead and report unavailable delegation. Never substitute an ad-hoc recursive shell agent.

Keep a capable lead responsible for the full outcome. Creative direction, visual judgment and motion require an appropriately capable lead and a reviewer with comparable judgment; do not select a lower-capability or lower-reasoning child merely for speed. Narrow mechanical work may use a narrower worker when its checks expose mistakes. If available controls cannot preserve an explicit choice, keep the work with the lead or report the limitation.

Give each worker the concrete deliverable, relevant source inputs, disjoint file/decision ownership, constraints, permitted effects and verification requirement. Identify dependencies so workers do not edit shared owners concurrently. Use existing coordination state rather than creating a second tracker.

The user freezes a task through `/mirket-task` with a task ID, deliverable,
project-relative output files, rubric and explicit provider/model/effort. Then
use `mirket_delegate` for one independent mechanical, creative-author or
creative-reviewer contribution; use `mirket_task_status` to inspect shared
counters. At most two managed children run concurrently, with one delegation
level. Child tools are scoped read/write/edit and runtime inspection; the lead
runs project commands and native renders. Creative review requires saved raster
files in the frozen output set and actual image delivery to the reviewer. A
completed child reports artifact identity, not a blanket quality verdict.

For visual or effect-bearing work, record the project root, allowed outputs (including authorized temporary destinations), requested or inherited reviewer/model settings and one shared repair budget. Check project-scoped outputs against that allowed scope; writing elsewhere is a scope failure. A host approval denial is a boundary result: preserve sources, report it, and stop the denied action rather than bypassing it; continue independent authorized work.

Integrate actual artifacts, resolve disagreements from evidence and run checks across boundaries. Worker confidence or a completed turn does not establish a completed deliverable. Stop delegation when work is no longer independent, ownership conflicts or required capability cannot be supplied. An interrupted turn does not prove its commands or jobs stopped: check their state through the owning host or job tools before claiming cancellation or reassigning overlapping work. Return contributions, integrated evidence and unresolved gaps without claiming that guidance technically enforces every spawn choice.

The budget covers every visual or motion specialist, reviewer, retry and repair; a new delegate or specimen never resets it. Resolve disagreement from the frozen rubric and saved artifact before adding a reviewer; the lead owns integration and checks rendered copy/bounds against the brief. Record the managed child’s bootstrap evidence for package/runtime, canonical project, requested and effective model/effort, and shared task budget. A fork, reload or new specimen must reuse that budget. Managed limits do not sandbox arbitrary shell commands or unrelated extensions.
