# OpenPencil design source

Verify the qualified Mirket OpenPencil file capability and select the project explicitly. Do not attach to the user's normal editor. Inspect existing source or a minimal native specimen before expanding the design.

Represent supported frames, components, fixed single-line text and fixed-size horizontal or vertical layout as editable structure rather than a flattened screenshot. Check the active capability contract before promising variants, wrapping, text shaping, embedded assets or responsive layout. Preserve source identity and avoid destructive conversion of the original. Use controlled fonts/assets with verified rights and available glyphs. Compile and consume shared design tokens when the deliverable requires them.

Save the design, reopen that saved file and make a representative text/layout or component change through the file workflow. Export the changed result and inspect layout, fonts, clipping and intended dimensions. A file extension, successful save or static preview does not prove editability.

Return the editable source, checked exports, reopen/change evidence and unsupported features. Unless the task sets another budget, share 15 minutes/two final repairs for static or vector work and 30 minutes/three for interface or paged designs, with one target repair; combined work uses the largest applicable limit. Stop when the required structure and export are verified or report unresolved defects at the limit. If the exact capability or font is unavailable, preserve source and report the gap instead of fabricating an editable deliverable.
