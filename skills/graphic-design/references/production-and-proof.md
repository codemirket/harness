# Production and proof

Use the sections that affect this deliverable. Confirm uncertain production
requirements from the destination or provider before a costly final export.

## Choose editable source and output

| Need | Suitable route | Evidence to inspect |
| --- | --- | --- |
| Photography, texture, painterly illustration | Supplied/licensed raster or the available imagegen workflow | Focal details, crop, resolution and artifact-free edges |
| Logo, icon, scalable flat illustration | Editable vector source and native SVG/vector tools | Real paths/text, silhouette, small-size detail and clean export |
| System or process explanation | Semantic diagram source, SVG or suitable diagram tool | Every relationship, label, branch and direction against the source |
| Quantitative chart | Data-backed plotting or spreadsheet workflow | Data, scale, units, labels and visual interpretation |
| Presentation, report or campaign layout | Native editable format, with linked or embedded assets as appropriate | Final pages/slides at delivery size and exported output |
| Animation or video | Existing motion tool and deterministic timeline | Playback, key frames, timing, captions and final encoded artifact |

Start from the requested medium and editability. Use a simpler available route
when it meets the need. Never promise vector editability from a raster image or
pixel-perfect typesetting from an uninspected generated image. Keep essential
text, labels and numbers editable where feasible. Keep the original source when
converting text to outlines or flattening for an export requirement.

## Respect facts, assets and rights

For material assets, retain the source, creator/license and relevant usage limits
in the project's existing asset record or a concise handoff note. A repository
license may exclude bundled fonts, stock images, brand marks or third-party
icons. Availability through a search engine does not establish reuse rights.
Check font embedding and redistribution permissions when delivering editable
files or packaged fonts. Use a fallback with suitable language coverage when
rights or availability are unclear.

Keep provided names, dates, values and claims accurate. Label illustrative data
where it could be mistaken for a real claim. Reference imagery can guide
composition without copying distinctive assets. Preserve required attribution.
Do not imply that an unaffiliated brand endorses the product.

## Resolve color and physical size

For ordinary screen delivery, use an appropriate web color space such as sRGB
unless the destination calls for another profile. Inspect the actual export in
its intended background and common display context. Wide-gamut choices need a
usable fallback when the consumer cannot preserve them. Color alone should not
carry essential distinctions in diagrams or information graphics.

For print, obtain the printer's trim size, bleed, safe area, requested PDF preset,
color profile, ink limits, spot-color and finishing requirements. Use the
specified conversion and preflight path. Do not claim a generic RGB export is
press-ready, invent an ICC profile or apply a universal bleed/resolution rule.
If requirements are unavailable, supply a clearly described proof and identify
the unresolved production step.

Evaluate raster resolution at its final physical size and expected viewing
distance; a DPI metadata number does not create missing pixels. Keep small type
and critical linework vector where the output supports it. Check rich-black,
overprint, transparency and spot-color handling when those features matter.
Display appearance alone cannot prove the printed color; distinguish a screen
proof, calibrated soft proof and printer/hard proof.

## Refine the design, then verify exports

Use three views: the whole composition at use size, a reduced view that exposes
hierarchy, and detail views of focal elements. Check type spacing and line breaks,
alignment, visual balance, grouping, crop, contrast and whether the intended
message survives. Decorative novelty is not a substitute for communication.

For illustrations, inspect anatomy or geometry as appropriate, repeated forms,
perspective, light, material, line weight and edge quality. For diagrams, compare
labels and edges to the source; attractive simplification must not erase a
condition or reverse a dependency. If the canvas becomes crowded, restructure
or split it rather than silently deleting meaning.

For each export, check:

- Correct format, dimensions, page/artboard count and output naming.
- Legible text and recognizable forms at the smallest intended use size.
- Cropping, safe areas and any required bleed in each destination format.
- Transparent edges on both light and dark backgrounds, or the intended solid
  background; no unintended matte, halos or missing layers.
- Fonts, linked assets and external references resolved as the consumer expects.
- Color/profile and compression suitable for the destination, without pretending
  an untested print or device path has been verified.

Compare a family together for coherence, then inspect each member separately.
Different aspect ratios may need re-composition, not just scaling or center-crop.
When a defect appears, repair its source and repeat the affected export and
inspection. Remove only owned scratch assets after useful output is retained.

## Handoff with useful limits

Provide editable source when requested or necessary for reuse, plus the agreed
exports. State which files were inspected and at what intended size. Include
material font/asset requirements and unresolved production constraints. If a
renderer, physical proof or target device was unavailable, identify it plainly.
Do not substitute a specification checklist for looking at the final artifact.
