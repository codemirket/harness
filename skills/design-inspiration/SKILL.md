# Design inspiration

Deliver a useful direction supported by inspected examples. Select references
for the decision they illuminate: a beautiful cover, popularity or a famous
creator does not establish suitability for this task.

The bounded [design-language index](references/design-languages/index.md) routes
selected instances and focused original practices to source/rights records and worked
examples. Use the material for inspiration, understanding, comparison or review
where it helps. Several references can illuminate the same question; a practice
needs no parent-card reading. The index is one discovery route alongside project,
native platform, primary and adjacent-domain sources. Its contrast exercises are
optional learning tools, not prerequisites for production work. The library does
not override user references or existing tokens, supply third-party brand assets
or prove a measured skill improvement.

If a broad relationship query has no complete reference keyword match, catalog
routing can return `design_reference_candidates`: bounded lexical suggestions
with matched/unmatched terms and use/avoid conditions. Candidate order does not
establish fit or choose an aesthetic. When suggestions miss the relationship,
reframe the query, use the index, pursue other sources or proceed from sufficient
existing evidence; ordinary keyword results remain separate.

When checking what this library represents, [coverage](references/design-languages/coverage.md)
explains the optional `catalog_search` `design_context` lookup and CLI `--family`,
`--platform`, `--interaction` and `--constraint` flags. These axes describe this
inventory; a brief need not fit them or use this lookup to proceed.
The response distinguishes represented, partial and unrepresented inventory,
shows each candidate's missing axes, and never claims current-task validation.
Source-only native guidance and a web teaching analogue do not establish a
native implementation. Missing inventory coverage can prompt relevant outside
research or a working slice when actual task uncertainty warrants it. Do not
combine unrelated cells to imply that RTL, offline, device or access needs are met.
The compact guide usually suffices; the registry provides exact axes/cell details.
Provisional reference candidates never change the scoped coverage result.

The focused [comparison practice](references/design-languages/comparison-at-use-size.md)
addresses independently wrapping headings that displace intended partner graphics,
or overflowing records whose continuation is hidden. The focused
[recovery practice](references/design-languages/recovery-feedback.md) addresses
obsolete rejection beside a corrected draft, including review/return when that
journey exists. They can help study or review those relationships; long labels,
paired values or a basic editable form alone do not require them.

## Frame the search

Recover the audience, medium, actual content, constraints and open decision from
the brief and existing work. Preserve accepted brand and product choices. Start
with user references; determine whether they want inspiration, a specific aspect
or faithful reproduction. Do not turn an implementation request into a research
deliverable or reopen a settled direction to collect alternatives.

Search by the unresolved relationship and its constraints: for example, bulk
selection in a dense operator table, a readable status-illustration family at
small sizes, or a narrative transition with a stable resting composition. Use
the project's sources and live primary examples where accessible. Galleries,
repositories and studio case studies can locate candidates; follow them to the
actual artifact and its creator rather than treating a thumbnail or catalogue
label as proof. Check whether apparently different references share one source.

When useful, search an adjacent medium or domain for a contrasting solution to
the same problem. Keep that exploration bounded by the open decision; novelty
alone is not a reason to replace a suitable example. Stop when the evidence
supports a concrete direction and further candidates repeat existing lessons.
There is no prescribed reference count. Honor explicit host/project resource
limits; choose useful comparisons rather than accumulating duplicate examples.

## Study what is available

Inspect the relevant content, composition and states with available native tools.
Record what makes the example strong for this brief, what conflicts with it and
which states remain unknown. A screenshot establishes the shown state; a video
can reveal a sequence but does not prove its implementation, keyboard behavior
or performance. Source code must connect to the inspected artifact before it
explains that artifact. Do not fill inaccessible evidence with invented detail.

For a reusable handoff or several candidates, use the compact
[reference record](references/reference-record.md). Reuse task notes or the
project's format; a separate board or report is optional. Keep observed facts,
interpretations and proposed adaptations distinct. Preserve capture context and
source identity so a later live revision does not silently replace the evidence.

## Transfer and hand off

Explain which inspected relationship transfers, why it serves the brief, what
must change and what remains excluded. Preserve the project's validation cadence
and saved-versus-draft boundaries; the example's components, palette and journeys
are not requirements. Derive concrete choices from the current content, brand,
tokens and semantics. When combining influences, resolve conflicting behavior,
hierarchy and visual rules into a coherent result. Do not copy source identity,
claims and assets merely because they are visible.
Record reuse rights separately from access to inspect an example.

Give the relevant existing owner an actionable direction, source locations,
constraints and an unresolved question to test in a small specimen when needed:
`interface-design` for working UI, `graphic-design` for illustration/composition,
`svg-creation` for editable vectors, and the relevant existing motion skill for
feedback, navigation, expressive scenes or vector choreography. Those owners
choose implementation and verify the actual result with their existing standards.

When an adaptation exists, compare the relevant output and reference locations
for unintended carryovers. Common visual grammar alone is not evidence of
copying; exact claims, identity, media and distinctive combinations need specific
inspection. Report located overlaps and rights gaps without similarity scores
or legal verdicts. Inspiration selection is not proof of usability, originality,
human acceptance or an improvement in the finished product.
