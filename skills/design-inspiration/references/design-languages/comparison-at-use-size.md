# A comparison must survive its placement

A focused original practice linked to [Vega linked analysis](vega-linked-analysis.md), not a new reference instance or a Vega runtime. It can be the chosen entry point without reading Vega first. The existing card retains its [source edition and rights boundary](vega-linked-analysis.md#source-edition-inspected-relationship-and-rights). This practice uses original fictional packing records.

## Choose this practice

Use it when separately wrapping headings may displace intended partner graphics, or required columns continue beyond the viewport without a visible cue. Long labels or paired values alone do not establish that problem. Shared-heading/stacked comparisons can preserve association; vertical records need no sideways cue. Choose Vega instead for an unresolved shared selection and selected-versus-total populations.

## The relationship being taught

A common numeric scale is necessary, but the rendered comparison also has a geometry. A long label can move one graphic away from its partner. A correctly scrollable table can conceal that another column exists. Inspect the actual small placement with the real label lengths, units and continuation; a screenshot of a spacious default cannot settle those relationships.

In the original [Packing bench practice](../../assets/design-languages/comparison-at-use-size/index.html), two methods use 44 and 28 minutes for an invented batch of 96 envelope sets. Both tracks represent 60 minutes. One method description is much longer. The numbers are constructed teaching content, not experimental evidence or a promise about productivity.

## Located decisions

- `.comparison` gives both method headings, values, tracks and calibration shared grid rows. Wrapping one description can increase the heading row without moving its track independently. At enlarged text sizes, runs can stack while retaining equal track widths and calibration. This is an organizing relationship, not a rule that every unrelated card must have equal height.
- `.scale` retains readable 0, 30 and 60-minute calibration at 320px. Exact values remain text beside the original graphic. A label may move or simplify when its role survives; removing the only visible calibration does not preserve that role.
- `#table-context` sits outside `#table-region`, so its sideways-continuation instruction wraps in the viewport rather than clipping with the table. The labelled native scroll region is keyboard reachable; the complete records remain in an actual table.
- View buttons retain the exact names “View Envelope sets” and “View Label sheets”. Their check/plus marks are separate `aria-hidden` spans; pressed state uses `aria-pressed`. Verify the browser's accessible names, not only visible text or an icon's apparent purpose.
- Saved-view restoration parses and validates a small schema before using it. Unreadable stored data selects an honest default and allows an explicit replacement save. A rejected read or write is a different condition: the current comparison survives, and a failed write leaves retry possible. Corrupt data is not proof that storage permissions are unavailable.

The button-name and restoration checks address implementation boundaries. Both variants keep these controls and recovery paths valid so the visual contrast can be judged separately.

## Polished misleading counterpart

Open `?variant=misleading`. Content, values, scale, selection, accessible control names and persistence remain the same. Each method flows independently inside its column, so a wrapping description displaces its value and track. The table-context text moves into the horizontally overflowing caption; at narrow widths the instruction is clipped beyond the visible edge. The result can look calm and complete while weakening alignment and discovery of the complete records.

## Transfer the relationship

Preserve identity/value/graphic association and common scale at the target placement. Couple slots where independent wrapping breaks alignment, or use a shared heading and stacked runs; different top positions alone do not disqualify intentional stacking. This example's shared rows are one option.

Use an outside continuation cue when required content actually extends beyond a clipping boundary. Vertical records can preserve retrieval without the table. Verify the actual access path rather than adding overflow to reproduce the example.

Set-switching and storage probes are auxiliary implementation boundaries. Do not add those controls or behavior to another brief. Preserve its saved/draft contract; this example does not authorize updating a saved comparison from unsaved input.

## Discriminating probes

These probes inspect the supplied practice; adapt them to the actual relationship and placement when transferring.

At 1280, 390 and especially 320px, choose Envelope sets and read the full long method description. Compare both tracks against the same labelled 0–60-minute ruler. Check their actual top positions: in the purposeful version they align despite different heading heights. Exact numbers alone cannot pass that composition probe. Repeat with Label sheets; do not shrink type or shorten the supplied description to conceal the issue.

At 320px, find the table's Recorded note column. The purposeful version visibly tells you more columns continue sideways before you focus the region. Tab into it and use Right to reach the notes, then Left to return. The misleading version remains operable, but puts its instruction inside the clipping boundary. Do not call hidden columns unreachable merely because the initial screenshot omits them.

Use the keyboard to change the selected set, save and reload. The selected identity, bars, table and saved label must agree. In an isolated practice browser context, put malformed JSON under `mirket-packing-view-v1`, then reload: the view stays usable, explains the default and can replace that entry by an explicit save. Also reject one write temporarily and retry after restoring it. Do not clear unrelated browser data or make a permanently disabled Save control the only response to a parse error.
