Selected instances teach different relationships. These are specific
platform languages, systems, case studies, interaction patterns and craft
grammars, not interchangeable complete component libraries. User references,
existing product systems and actual content govern selection.

## Optional inventory lookup

When inventory coverage matters, [coverage.md](coverage.md) and the exact axes in
[coverage.json](coverage.json) explain structured catalog requirements. They
distinguish a represented combination from a partial reference or a deliberate
gap. This lookup is not a prerequisite or an assessment of whether a design is
possible. An interface family is not a
platform, and a language reference is not evidence of current-task quality.
The registry keeps each instance/platform cell separate. It never pools a web
example's RTL support with another source's native guidance to imply native RTL
coverage. Native/device execution, offline sync, concurrent editing and actual
assistive-technology journeys remain explicit limits.

Search by source, alias or purpose: `mirket catalog search "Porsche"` or
`mirket catalog search "statistical uncertainty"`. The existing skill result
includes bounded `reference_matches` with exact lesson/example resource routes.
If more than five match, narrow the question or read this index. No reference
body is loaded by search. `mirket catalog show design-inspiration` locates the
machine-readable [library.json](library.json). Its small schema 2 index points to
one bounded `instances/ID.json` source/rights record per instance. For a canonical
instance, fetch only its selected record and lesson through existing delivery.

After no complete keyword match, CLI/MCP routing may also return a separate
`design_reference_candidates` field. It compares informative words with positive
canonical metadata and returns at most five provisional lessons with matched
terms, unmatched terms and use/avoid conditions. It leaves ordinary search
results and scoped coverage unchanged. It requires several informative query
words and at least two positive metadata matches, and suppresses common explicit
negators such as “no”, “don't”, “avoid” and “excluding”. These conservative
English lexical rules do not interpret every exclusion or infer intent. A missing
candidate is still a gap in discovery. Read the source record and decide fit from
the actual brief.

Choose material for what it contributes to the question. Comparing several
accounts of the same relationship can reveal assumptions or useful differences;
one reference or none may also suffice. A practice does not require its parent
card. These are discovery suggestions, not a required reading chain or a closed
set of sources. Respect explicit host/project resource limits and keep material
uncertainty visible. Reconcile influences against the actual content, behavior
and governing product system rather than reproducing a collection of styles.

| Focused practice | Use when this relationship remains unresolved | Avoid as a default when |
| --- | --- | --- |
| [Comparison at use size](comparison-at-use-size.md) | Separately wrapping headings may displace graphics intended to compare in one row, or required records continue beyond a clipping boundary without a visible cue. | Only paired values/long labels are known, or shared headings/stacking and vertical records already preserve association/retrieval. |

Do not add a review journey. |

These original exercises are not additional reference instances or claims of
broader platform coverage. Their linked canonical cards retain source context;
choose those cards when their distinct relationship is needed.

## Ways to reason with a reference

The following techniques serve different questions; use or adapt those that help:

- Compare a lesson's use/avoid conditions with the brief. A famous brand alone
  does not establish fit. Other project or external references may explain it better.
- Inspect a source's relevant states to substantiate a claim. Its captured digest
  identifies bytes, not an interaction audit or permission to copy them. Keep
  unavailable evidence explicit and preserve source/rights limits.
- Study an original example beside `?variant=misleading` to locate the relationship
  the plausible wrong version loses. This contrast is an optional learning or
  critique exercise; a reference can inform work without running it.
- Adapt a relationship, compare competing interpretations, or reject it. Derive
  the result from actual content, tokens and platform. The example's components,
  geometry, validation cadence and journeys are not production requirements.

Verify the actual artifact against the brief at intended sizes and states,
including access, truthful state, units/structure and conceptual fit. Code passing
or a screenshot does not establish that people understand the intended meaning.

## Read and render through existing delivery

Cards use `mirket catalog read design-inspiration --path references/design-languages/ID.md`.
`skill_read` takes `skill_id: design-inspiration` and the same `path`; resources
use `mirket://skills/design-inspiration/references/design-languages/ID.md`.
HTML sources use `assets/design-languages/ID/index.html` under the same owner.
Catalog/resource reads return source text. Open the saved/installed HTML with an
available local-file browser for pixels and interaction. If HTTP is needed, use
an available local server; for example, with an existing Python installation:

```sh
python3 -m http.server 8847 --bind 127.0.0.1 --directory /absolute/path/to/design-inspiration
```

Visit `http://127.0.0.1:8847/assets/design-languages/ID/` and append
`?variant=misleading` for the contrast. Use the actual installed skill path;
serving the skill root keeps relative card links usable. Every example is
standalone, with system fonts and original inline code/vector artwork, without
network dependencies. Read and inspect the selected lesson and sample within
the task's resource limits, not the entire library.

For project delivery: `mirket project add --project PATH --skill design-inspiration`,
then `mirket project sync --project PATH` and `mirket project doctor --project PATH`.
This uses the established target layout for Codex and Claude; no new design
package, runtime or activation claim is introduced.

## Provenance and reuse

The [index](library.json) locates each canonical record of exact external sources, inspected edition,
check date, rights scope, license link when known and captured response digest
or an explicit retrieval gap. Website captures can be mutable HTML shells;
`capture_note` records that limit. No network fetch occurs during catalog use.
Re-check current official guidance for a live product decision; a historical
instance remains useful only within its stated scope.

External sources and brand assets are **link-only**. An open-source framework
license does not automatically license its fonts, illustrations, logos, content
or current website. The library ships original Mirket commentary and specimens
under [MIT](../../assets/design-languages/LICENSE.txt); it does not ship those
third-party assets. Upstream asset admission, if needed later, requires exact
files, source revisions, applicable notices and explicit scope review.

## Evidence that can improve the harness

Use held-out briefs that require different content and compare the baseline
harness with the library-assisted harness at the same model/settings. Include
appealing wrong variants, long copy, errors, reduced motion and small placements.
Have an independent reviewer distinguish conceptual defects, accessibility
defects and taste. Record located evidence, cost/latency and unverified paths;
do not infer a measured capability gain from these worked examples alone.
