# Dependency admission

Establish the concrete capability gap and alternatives within existing dependencies. Identify the exact version/source, transitive closure, platforms/architectures, package hashes and build/runtime entry points. A source reference, install receipt or name match is not admission.

Inspect license/source/notice obligations for the exact payload, including bundled binaries, assets/fonts, model terms and optional compiled features. Identify build scripts, installers, hooks, network fetches, telemetry, native prerequisites and credential/account effects without executing them incidentally. Check maintenance and compatibility at the affected boundary.

Prepare a reviewable admission record with benefit, tradeoffs, closure and qualification probes. Respect the project's existing dependency authorization; ask before a new production dependency unless its exact batch is already approved. Verify the actual packaged capability and a meaningful refusal/failure case separately from rights and installation.

Return the candidate decision and unresolved gates. Stop adoption when authorization, rights closure or required platform evidence is missing. Do not silently substitute a global executable, runtime download or differently licensed build.
