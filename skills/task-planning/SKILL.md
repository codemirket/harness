# Task planning

Inspect the intended outcome, project instructions, affected owners, current changes and available tools. Resolve routine implementation choices from evidence. Ask only for a missing decision or authorization that changes the work; advance useful independent work while it remains unresolved.

Define the deliverable, constraints and observable acceptance before sequencing. Order tasks by dependency and the uncertainties with the greatest cost of being wrong. Include the failure/recovery path when it determines feasibility. Name a responsible owner and concrete verification for each meaningful boundary, without expanding a small request into a broad program.

Use the project's existing record if continuity, recovery or coordination warrants durable state. Preserve decisions, source revisions, completed evidence and the next unresolved action there. A short single-session task needs no parallel tracker. Planning does not itself authorize external effects, dependencies, commits or agents.

Return an executable sequence with decision gates and a stop condition. Revise the sequence when evidence changes a dependency; preserve the intended outcome rather than silently deleting a difficult requirement. Stop planning once the next action and acceptance are clear, then execute within authorization. Stop dependent execution only at a concrete missing prerequisite or decision.
