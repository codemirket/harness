# Search audit

Define the affected pages, audience, search engine, and business outcome. Separate
an observed crawl/indexing failure from a content, relevance, or conversion
hypothesis. Start with the requested problem rather than a site-wide checklist.

## Establish the evidence

- Inspect live responses, canonical declarations, redirects, robots directives,
  sitemaps, rendering, and internal links for the affected URLs. Trace a sample
  through the actual chain rather than judging isolated tags.
- Use the owner's search console and analytics when available. Record dates,
  segments, and coverage limits. A public search result is an incomplete view of
  indexing; absence from a search query is not conclusive evidence of exclusion.
- Check current official search-engine documentation before recommending
  structured-data features, rich-result eligibility, crawl controls, or metrics.
  Do not recommend retired tests or assume every schema vocabulary creates a
  supported search feature.
- Treat canonicalization as a signal to investigate, not a guaranteed directive.
  Consider the interactions of crawl access and indexing controls before changing
  robots rules or noindex; a blocked crawler may not see page-level instructions.

## Prioritize improvements

Connect each finding to a reproduced example, affected page group, likely impact,
and specific remedy. Separate technical faults from content opportunities and
unverified ranking hypotheses. Avoid universal word counts, keyword densities,
or promised rankings. Useful content answers the audience's question accurately;
new pages need a distinct user purpose and evidence, not scaled keyword variants.

Validate redirects, metadata, structured data, and navigation after changes.
Use the relevant rendered and source representations, and check that the fix does
not hide useful pages or create redirect loops. Report what was verified locally
and which outcomes require later crawling or measured traffic. Submit external
changes only within the user's authorization.
