# Capability contracts

Workflow coverage, not certification or automatic runtime activation. Select supporting skills only for affected boundaries.

Generated from `registry/capabilities.json` by `python3 ai.py capabilities list --markdown`.
Use `capabilities show ID` for selection details and `capabilities check` for source integrity.
These are required outcomes and failure probes, not claims that every domain has passed a production trial.

| Capability / ID | Lead | Deliverable | Discriminating failure probe | Prerequisites |
| --- | --- | --- | --- | --- |
| Frontend Engineering (`frontend-engineering`) | `frontend-engineering` | A working user journey with explicit loading, empty, error and durable-success states. | Reverse response order and repeat a mutation; older intent must not win and durable effects must not duplicate. | Actual framework runtime and browser; backend boundary for durable effects. |
| Backend Engineering (`backend-engineering`) | `backend-engineering` | A versioned service contract exercised through authorization, persistence and failure recovery. | Replay an idempotency key with another payload and simulate commit-before-timeout. | Target language/framework, isolated datastore and controlled dependency. |
| Brand Guidelining (`brand-guidelines`) | `brand-guidelines` | An editable brand guide with semantic tokens, voice examples, asset rules and real specimens. | Apply the rules to a dense screen and a small/dark asset; expose conflicting tokens or illegible marks. | Approved brand inputs or explicitly proposed direction; renderer and font/asset rights. |
| Web Design (`web-design`) | `interface-design` | Rendered pages with purposeful composition, real content, responsive states and working interactions. | Use long real labels and narrow width; the primary action and content hierarchy remain usable. | Local app/browser; supplied, existing or explicitly proposed design direction and content. |
| Mobile Design (`mobile-design`) | `mobile-design` | Platform-specific navigation, touch/input, accessibility and state recovery verified in context. | Open the keyboard, enlarge text and return via back navigation without losing entered state. | Named native/web platform; simulator for native build/layout; physical hardware for touch, keyboard and gesture claims. |
| SEO Expertise (`seo`) | `search-visibility` | URL-level crawl/index/content findings tied to observations and an ordered remediation plan. | A robots-allowed but noindex page must not be reported indexable; inaccessible Search Console stays unknown. | Authorized public URLs; current search-provider docs; dashboards only when available. |
| Deep Researches (`deep-research`) | `research-and-synthesis` | A source-linked synthesis with claim-level support, counterevidence, applicability and unresolved uncertainty. | Introduce conflicting versions and a syndicated copy; neither stale claims nor duplicates become independent support. | Search/retrieval tools and primary sources; access limitations recorded. |
| Interface QA Engineering (`interface-qa`) | `test-design` | A defect report from exercised roles/states with reproducible triggers, expected results and exact visual evidence. | Break keyboard focus return and inject a stale response; catch behavior defects despite a good screenshot. | Real browser and app; a11y tools/screen reader where required. |
| Illustration (`illustration`) | `svg-creation` | A coherent original illustration composed for its placement with editable geometry or the requested raster source. | Inspect the actual crop and small-size silhouette; a raster wrapped in SVG fails editable-vector requirements. | Vector renderer; for raster choose the available native image-generation skill/provider instead of the vector lead. |
| Crafting Visual Assets (`visual-assets`) | `svg-creation` | A consistent asset family with master sources, export sizes, naming and integration contracts. | Place two inline instances and render light/dark/minimum sizes to reveal ID collisions or disappearing detail. | Existing vector/image tools, asset rights and target consumer; for bitmap assets select the native image-generation/editing workflow instead of the vector lead. |
| Animation (`animation`) | `motion-design` | Motion that communicates actual state, handles interruption and preserves reduced-motion functionality. | Reverse or cancel midway, unmount and change motion preference; no stale state or trapped control. | Actual UI engine/browser; native platform or video renderer for those distinct deliverables. |
| Project Review (`project-review`) | `architecture-review` | Prioritized findings with concrete triggers, affected consumers, consequences and a scoped repair plan. | Seed a plausible cross-boundary defect; the review must trace it rather than list generic best practices. | Repository/history, runnable relevant checks and stated review boundary. |
| Planning (`planning`) | `work-planning` | An executable sequence with dependencies, decisions, ownership, acceptance evidence and resume state. | Change a blocking assumption halfway; dependent work and the durable plan must reconcile. | Authoritative brief and current project state; no extra runtime required. |
| Product Management (`product-management`) | `product-management` | A defensible product decision, bounded delivery slice, guardrails and measurement contract. | A loud customer request with no population baseline must not become invented universal demand. | Actual customer/product evidence and decision owner. |
| Database Expert (`database`) | `database-systems` | Correct constraints, representative query plans and migration/recovery evidence on the named engine. | Interrupt a batch and resume under old/new writers; preserve every row and invariant. | Named database engine/version, representative isolated data and recovery path. |
| System Engineering (`systems-engineering`) | `systems-engineering` | A coherent system model, capacity/failure analysis, contracts and a verifiable operational design. | Fail a dependency or exhaust a bounded queue; identify propagation, backpressure and recovery. | Target topology, workload/limits, telemetry and an isolated failure experiment. |
| Devops and Infrastructure Engineering (`devops-infrastructure`) | `infrastructure-engineering` | Reviewed infrastructure plan and reproducible build/release/recovery evidence for an exact target. | Present stale plan, secret-bearing output or mixed-version rollback; detect invalid assumptions before changes. | Existing IaC/build/runtime tools and explicit target access; production mutation requires task authorization. |
| Marketing Expert (`marketing`) | `marketing-writing` | Audience-specific positioning/copy with traceable claims and channel fit; a measurable experiment when the task requires one. | Remove the claimed proof or change offer conditions; revised copy must retain truth and qualifications. | Approved offer, customer evidence and channel context; publication/spend separately authorized. |
| CEO perspective (`executive-strategy`) | `executive-strategy` | A strategic choice connecting customer value, economics, capacity, cash timing and reversibility. | Stress adoption, margin or capacity assumptions; show when the recommendation changes and who decides. | Actual business facts; explicit hypothetical labels for absent financial/market evidence. |
| Data Analysis and Deep Understanding (`data-analysis`) | `data-analysis` | Reproducible reconciled analysis with grain, units, population, missingness, alternatives and a supported decision. | Duplicate joined rows and shift segment mix; totals reconcile and aggregate uplift is not mistaken for causality. | Authorized data and query/script/workbook runtime; source meaning beyond column names. |
| Project Scafolding (`project-scaffolding`) | `project-scaffolding` | A minimal runnable project or vertical slice with verified startup, tests, config and ownership. | Scaffold into a nonempty repository with existing conventions; preserve all unrelated files and detect conflicts. | Chosen stack and available generator/toolchain; no automatic dependency install or unrelated framework. |
| Design Revisioning (`design-revision`) | `interface-design` | An attributable revision preserving approved constraints, working behavior and comparable before/after views. | A polish request must not silently change labels, brand identity or data behavior; compare identical states. | Baseline source/renders, requested revision scope and existing tokens/components. |
| Efficiency and Optimization Expert (`optimization`) | `performance-engineering` | A measured bottleneck fix with correctness parity, representative workload and repeatable before/after measurements. | A faster run with changed inputs, warm cache or weaker correctness must not count as an improvement. | Target profiler/load/query tools, comparable runtime and data; cost limits where relevant. |
