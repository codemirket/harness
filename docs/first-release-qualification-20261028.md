## Retention decision and changes

The user adopted an evidence-led retention rule: skills must justify their
context and maintenance cost through useful output, a concrete route contract
or a non-obvious quality safeguard. Catalog size is not a goal. The rule is
recorded in `AGENTS.md` and the catalog/release plans.

The tested product bundle is removed: `customer-research`, `product-strategy`,
`positioning`, `marketing-copy`, `conversion`, and `experiments-launch`, including
their six resources (21,008 body/resource bytes removed). All 61 retained skill
bodies are byte-identical to the preceding catalog. The `content-growth` profile and web-product's conditional
conversion selection are removed. Codex retains those ordinary workflows.
`jobs-to-be-done`, `prototype-test` and `content-search` remain selectable.

This decision uses two valid matched comparisons: both enabled bundles timed
out at 180 seconds without artifacts; their no-skill baselines independently
scored 12/12. It does not attribute failure to any individual member or relabel
the failed results as successes. No more model trials were run for this closure.
The [original evaluation](supplemental-model-evaluation-20261028.md) retains all
attempts, budgets and limits. The remaining 9 global / 52 project / 7 profile
catalog contains 305 planned development cases, not 305 completed acceptance
trials. Broader causal quality uplift is not a release claim.

| One-second collector test depended on Python startup under concurrent build load | Use a shell builtin to emit the test event before sleeping; collector behavior and deadline unchanged | Original failed suite retained, focused test passed, full 232-test rerun passed with one existing skip |
