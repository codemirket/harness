### Fixed: browser response metadata changed representation semantics

`pi/src/extension/browser-proxy.ts` generated Content-Length from received body
bytes for every response. HEAD and 304 have no response body but may describe a
nonempty representation. A nine-byte upstream resource became Content-Length 0.
The proxy also discarded Cache-Control, Expires and Vary while forwarding ETag,
losing the upstream cache policy and variant identity.

The correction preserves upstream representation length for HEAD/304, leaves
unknown lengths absent, omits forbidden Content-Length on 204, and forwards the
three cache-policy headers. Ordinary body-bearing responses still use the
measured, bounded byte count. Cookies, redirects, attachments, nonidentity
encoding, remote origins and non-GET/HEAD requests remain refused or stripped.

The regression failed on the previous implementation (`'0' !== '9'`) and passed
after correction. Real loopback HTTP tests cover known/unknown HEAD lengths,
304 revalidation, 204, no-store/Vary, the existing refusal cases and a response
over the 16 MiB limit. This is local proxy evidence, not whole-browser or network
sandbox qualification.

### Fixed: adapter build did not enforce its direct dependency lock contract

`pi/scripts/build.mjs` checked external Pi peer versions but imported TypeScript
without checking the installed adapter's own required dependencies against its
manifest and lock. A stale direct dependency could silently participate in a
successful build despite the documented locked-input requirement.

`pi/scripts/check-dependencies.mjs` now checks direct production/development
inputs against the npm v3 root and package entries and installed names/versions
before the compiler import. It downloads nothing. Disposable tests cover missing
inputs, mismatched installed/locked versions, a changed manifest and an exact
passing tree. This is a version/lock consistency guard, not a cryptographic audit
of every installed transitive source file.

### Fixed: global upgrades left initialized project package pins stale

`scripts/migrate-pi.py` updated the global package object only. A project enrolled
through `/mirket-project init` retains its own old package path, so entering it
after an upgrade can load the old extension against the new native identity.
The current repository has exactly this project-specific pin.

Migration now accepts repeated, explicit `--project` roots (maximum 32). It
validates the selected old package object, holds renewed Pi settings locks,
backs up original bytes/modes and before/after identities, and changes only that
object's source. It never discovers projects. Unselected projects are unchanged.
Concurrent edits, aliases, duplicate selections/JSON keys, missing old objects
and busy settings refuse rather than overwrite. Partial multi-project publication
retains named backups and the exact failed phase; it is not presented as an
all-files transaction or silently rolled back. Release-bound project consent
still requires explicit `/mirket-project init` after restart.

Disposable tests exercise preservation, refusal, concurrent drift and failure on
the second project after publishing the first. Actual standalone migration and
project-consumer results belong to the separate release qualification record.

## Website replacement

`website/index.html` and `website/style.css` are a new dark, compact composition:
short introduction, a three-part responsibility strip, six concise capabilities,
installation steps and an explicit qualification note. Legal and error pages use
the same visual system. Original logo bytes and provenance, public URLs, release
links and the same-origin CSP contract are preserved. There are no fonts fetched
from another service, scripts, framework or new dependencies.

The new static tests check page/fragment targets, local assets, unique IDs, one
primary heading per page, script/inline-style absence and the public logo alias.
A deliberately unsafe/broken fixture checks that the parser exposes those defects.
Actual Chromium 156.0.8078.73 checks covered all three pages at 1440, 768, 390 and
320 CSS pixels: no horizontal overflow, loaded images, keyboard skip/focus and
installation/legal/home navigation. Saved desktop, mobile, legal and error-page
pixels were inspected. This is not a screen-reader or comprehensive accessibility
certification. The private browser was explicitly selected and hash-checked;
no installation or first-use browser download ran.
