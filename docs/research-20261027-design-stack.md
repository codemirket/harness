## What to learn, and what not to import

### Hallmark and Taste: retain the distinctive decision method

The current authored skills already preserve subject-derived art direction,
structurally different specimens, real content, responsive states, saved-pixel
inspection and a shared repair budget. The implementation is not a wholesale
copy of either project, and the current comparison-only provenance is accurate.

The targeted audit nevertheless found that the earlier broad audit was too
generous about fidelity. Several useful methods are diluted into general advice:

1. For an open-ended visual brief, collect a short inventory of facts specific
   to this subject, and turn one into a visible compositional idea. Test whether
   the same result could be relabelled for a competitor without meaningful change.
2. Compare structurally different directions only when direction is unresolved;
   record why the selected one fits. Do not reopen an accepted user direction.
3. For public pages, connect claims to supplied or verified proof. Missing proof
   must lead to a labelled placeholder or a different composition, not fabricated
   metrics, testimonials or client logos. General honesty already requires this;
   the source adds an explicit design decision method.
4. For an existing project, identify actual route/component/token/font/motion
   owners and the authorized edit scope before changing its visual language.
5. For component work, make hover and pressed states explicit alongside default,
   focus, disabled, loading, error and success where applicable.

These are static adoption gaps and hypotheses for output improvement, not newly
demonstrated model failures. Keep the methods conditional and compact. Do not
import arbitrary numerical quotas, fixed house styles, random direction engines,
third-party asset rights or unnecessary confirmation gates.

Approved pins and exact source/body/license evidence are in the companion audit.
Fresh upstream branches need their own comparison before adoption. The specialist
also inspected current Hallmark v2 and Taste v2.1.5 drift. Taste's separate classic
GPT/Codex variant is not an automatic upgrade: its mandatory AIDA, GSAP, stock
image and randomization choices conflict with our selective, project-aware use.

### MengTo: the clearest illustration opportunity

The current `vector-art` skill is strong on editable geometry, SVG hygiene,
optimization, rights and before/after rendering. It teaches less about how to
construct a convincing illustration: pose, anatomy, contact, silhouette, focal
props and a coherent visual grammar.

[MengTo's illustration resources at the inspected revision](https://github.com/MengTo/Skills/tree/a45892d2fdadab75b31fb16abecc02f101b31c43/agent-skills/illustration)
provide style-specific instructions, style contracts, SVG examples and craft
references. The reported collection has 14 styles and 42 original example cards.
The valuable method is pose/geometry construction followed by whole-image and
magnified inspections of hands, faces, feet and contact points, plus structural
linting and a fresh-subject holdout. Its own judge scores are not our evidence.

Recommendation: an on-demand illustration craft resource within a narrow project
skill, using Codex to author and the existing qualified Mirket SVGO/resvg route
to optimize/render. Avoid loading every style into global guidance. Preserve
editable SVG for requested vectors; use host image generation only when the
deliverable calls for a bitmap. No new rendering engine is justified by this gap.

### Emil and Impeccable: combine craft with contextual judgment

[Emil's inspected animation skill](https://github.com/emilkowalski/skills/blob/2d228630ba1446365f614a108cb8252f1feda202/skills/animate/SKILL.md)
starts with purpose and frequency, chooses a suitable driver, then addresses
timing, origin, interruption, exit and accessibility. Its performance material
distinguishes actual symptoms and causes such as main-thread work and excessive
style recalculation. These fit `ui-motion`, `scroll-motion` and critique well.

Do not transplant its blanket bans, universal timing ceilings, compulsory
fan-out, stop-and-wait workflow, or recommendations to use cheaper executors
for motion judgment. Our capable lead, explicit user choices and single budget
take precedence. Transform/opacity use alone does not establish smoothness.

[Impeccable's inspected motion reference](https://github.com/pbakaus/impeccable/blob/d34c87e1a00989ae8dbdd7f6b30b70f23319e860/skill/reference/animate.md)
is a useful counterweight: distinguish persuasive/experiential surfaces from
operational/reading surfaces, choose one focal sequence where appropriate,
preserve continuity, and select motion material by meaning. It permits measured,
bounded masks, filters and other treatments rather than treating every property
outside transform/opacity as intrinsically wrong.

The current Impeccable repository also includes a binary, launcher, hooks and
live browser workflow. Do not import those as incidental dependencies. Its
craft-floor guidance contains a Codex-specific blanket restriction on
figure-bearing SVG illustration; that is unsuitable as a universal rule for
this user's editable, artful illustration goal. Select useful methods rather
than stacking whole upstream skill packs with conflicting mandates.

### Huashu: a director layer that complements HyperFrames

Inspected commit: `4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1`.
The [storyboard resource](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/references/storyboard-basics.md)
designs keyframe composition before animation code: focal subject, visual
hierarchy, layers, setup/payoff, motivated camera movement, reading/hold time,
and transitions chosen from the relationship between adjacent scenes. A compact
shot card also chooses acceptance frames before implementation. These are more
useful than another catalogue of fade-in effects.

Its [backend guide](https://github.com/alchaincyf/huashu-design/blob/4fc7bfdbd5ec3fa2d43ce7a6433de60976a5e4b1/references/hyperframes-backend.md)
explicitly defaults new animations to HyperFrames. That supports treating
creative direction and rendering as separate responsibilities. However, the
guide's tested version, installer commands, alternate render paths, global skill
writes, remote font handling and blanket contrast-check exceptions are not our
qualified contract. Do not execute/import them. Author against our exact pin and
admitted local assets instead.

Useful adaptation: a brief shot card, keyframe contact sheet, deliberate
continuity between scenes, and actual decoded-output comparison. Do not import
universal no-hard-cut rules, exact word/element/zoom quotas, mandatory three-way
approval, a separate preference-memory system, or a new voiceover/renderer stack.

Saved upstream Hokusai and birding-app showcases were displayed with an
image-capable tool. The Hokusai page uses the subject artwork as a full-frame
composition and oversized typography at the bottom. The birding app carries a
bird-sticker concept consistently through recognition, collection, detail and
map screens, using a yellow/black palette and a dotted notebook surface. These
are concrete examples of subject-derived design. They establish neither our
generation ability nor the screenshots' interaction, accessibility or rights
for reuse. Taste's live Aurora and Northstar samples were also visually viewed;
they are curated examples, not reproducibility tests.

### UI UX Pro Max and Open Design: useful, different roles

[UI UX Pro Max at the inspected revision](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/tree/28b3b8dee8c976df4fa3e94aed4e092ad43fcb03)
offers searchable UX/design/stack material and a local Python lookup workflow.
Its query discrimination and actual-stack detection are useful. Treat its style
and industry presets as options, not proof that a layout fits this product.
It should supplement Hallmark/Taste's concept work rather than override it.
The optional lookup scripts and data are not currently admitted runtime inputs.

[Open Design at the inspected revision](https://github.com/nexu-io/open-design/tree/b7c5dd6d350bf54587a76bef1899bcbc183ea59d)
has substantial public interest and broad design-workspace scope. Its agent
runtime adapters, model/session machinery and integrated tools overlap the
responsibilities Codex already owns. Study specific transferable methods if
needed; do not install another general agent workspace inside Mirket.

## HyperFrames diagnosis

Keep HyperFrames. Several observed problems were demonstrably elsewhere:
host approval stopped a model request before server execution; a non-video
creative retry wrote outside its requested project; fixtures omitted required
assets/elements; and the wrapper scanner raced a transient Chromium directory.
The wrapper race was repaired and repeated runs passed in earlier qualification.

The authoring contract also matters. An unregistered Anime animation can yield a
valid export with a frozen intended object. Whole-frame changes alone can hide
that error. Test the intended object at chosen times, and retain actual decoded
frames. The current skill needs more explicit pin-matched composition/timeline
guidance, not a different renderer.

It would nevertheless be inaccurate to assume every issue is independent of
HyperFrames. The pinned 0.8.197 has a documented no-timeline readiness wait;
later upstream versions change that behavior and repair other renderer edges.
The next version comparison should hold source, wrapper, browser, codec tools
and assertions fixed while changing only the admitted HyperFrames version.
No such fresh comparison was performed here, and no upgrade was made.
