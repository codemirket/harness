# Engineering source review

Reviewed 2026-10-06 from primary GitHub pages and fresh shallow source checkouts. No upstream installer, renderer, hook, package code, or test was executed. Findings describe inspected instructions and code, not measured quality/performance or runtime certification. Coverage is detailed per source below.

## Recommendation

Use one small original engineering judgment skill globally. Offer separate debugging, test design, domain modeling, and architecture review recipes only where useful. Do not globally install any of these four whole bundles. Their strongest techniques are more useful than their full process prescriptions for this user's preference for autonomy and minimal overhead.

The cleanest unmodified project opt-in is Matt Pocock's `skills/engineering/domain-modeling/` (include its two reference files). It has no executable dependency or cross-skill requirement. It assumes `GLOSSARY.md` and `docs/adr/`, so installation should document that the project's established locations take precedence. `skills/productivity/handoff/` is also a compact, portable manual command, although outside the four requested subject categories. All other selected engineering skills need adaptation or explicit acceptance of their workflow dependencies.

- Risk: description triggers for practically any codebase question. Existing graph is queried first without a freshness gate in the fast path. Saved answers become graph inputs; secondary synthesis can be mistaken for original evidence. Always verify a material claim against current source.
- Risk: skill Step 1 auto-installs/upgrades `graphifyy`, falling back to `pip --break-system-packages`. It checks Gemini key presence and uses Gemini automatically for document extraction; otherwise host-agent extraction can consume substantial context. User should explicitly choose local code-only versus semantic/provider-backed processing.

Codex variant names `close_agent`, which this session does not expose. Installers can edit user/project CLAUDE.md and hook settings; especially relevant because this user's global files are shared symlinks.
- Runtime: Python >=3.10; networkx, numpy, rapidfuzz, many tree-sitter grammars; optional PDF, office, graph databases, video/transcription, model backends. Native Windows skill exists, but host and OS variants need deliberate matching and validation. macOS/Windows library support is not proof that every skill command works on every host.
- Accept only as a separate approved tool integration, pinned environment, explicit corpus boundaries, no automatic instruction injection/hooks, no automatic provider switching or upgrade. A wrapper should call supported CLI operations rather than copy the 700-line orchestrator.
- Coverage: full canonical skill, complete Codex diff, Windows installation/interpreter/cleanup changes, package/dependency manifest and all license notices; installer destinations/registration/hook paths; full query and hook references; extraction reference. Other host variants inventoried, not individually audited. Entire Python implementation and all optional exporters not audited.

## obra/superpowers

- Commit: `8ca22dba9a94f28898bbce59f2537ff4d87c747d`; MIT, Jesse Vincent copyright.
- Fifteen skill bodies all read. Package setup/README, SessionStart hook, and references for debugging, test design and review inspected. Other scripts/visual companion not fully audited; no runtime tests.
- Recommendation: **exclude whole plugin and its automatic bootstrap**. Adapt selected techniques in original skills; retain upstream as reference rather than direct installation.
- `skills/using-superpowers/SKILL.md` requires invocation before any response at even 1% relevance. SessionStart hooks inject this on startup/clear/compaction. Broad constant process is an explicit mismatch for this user's preferences, even though the skill acknowledges user instructions take precedence.
- `brainstorming`: repeated mandatory approvals even bounded work; architectural spec then written-spec approval then plan review/execution choice. Useful intent/constraints/alternatives concepts; exclude workflow.
- `writing-plans`: practical interface/verification/task dependency planning but compulsory downstream execution skills, frequent commits and additional approval handoffs. Adapt only complexity-based planning.
- `executing-plans`, `subagent-driven-development`: elaborate ledgers, review packages, per-task commits, mandatory specific review arrangement and model selection/escalation. Exclude universal use. A user can separately opt into the full methodology, which is a different product choice than this catalog.
- `systematic-debugging`: strongest source for backward causal tracing and hypothesis experiments; adapt. Compulsory phases, escalation after arbitrary three attempts, full reference reading, unsupported success percentages and secret-bearing environment-dump examples should not be carried over.
- `test-driven-development`: useful red/green checks and behavior-based tests; do not copy instructions to delete existing code, tests for every function, unconditional full suites, or approval-required exceptions.
- `verification-before-completion`: evidence before claims is valuable; requiring a fresh full command in every message forbids valid unchanged evidence reuse. Existing AGENTS already handles this better.
- `receiving-code-review`: check claims against actual code and defend correct choices. Exclude mandatory stop-all-work for one ambiguous item and rigid conversational bans.
- `requesting-code-review`: grounded file-line findings and separate spec/quality assessment worth adapting. Mandatory reviewer dispatch and model/harness assumptions not retained.
- `dispatching-parallel-agents`: independent scope/ownership is useful but already in global guidance; no standalone global duplication.
- `using-git-worktrees`, `finishing-a-development-branch`: native tool preference/provenance awareness good; dependency installation guesses, automatic .gitignore commits, repeated complete suites and rigid menus conflict with local conventions/autonomy.
- `writing-skills`: routing descriptions, disclosure and actual behavior evaluation useful; conflicts with existing skill-creator, imposes TDD/deletion and mandatory multi-run/subagent tests on every edit, then commit/push. Exclude direct installation.
- `diagnosing-superpowers`: maintenance of Superpowers itself, seven mandatory analysts and transcript processing; exclude.
- Portability: prompt concepts portable; plugin has Codex/Claude integrations and Bash hooks plus Windows launcher. Scripted workflows assume shell tools, git and dispatch interfaces; not a copy-one-file cross-platform bundle.
- Evidence: [bootstrap](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/using-superpowers/SKILL.md), [hooks](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/hooks/hooks.json), [debugging](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/systematic-debugging/SKILL.md), [test quality reference](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/test-driven-development/writing-good-tests.md), [fresh-command mandate](https://github.com/obra/superpowers/blob/8ca22dba9a94f28898bbce59f2537ff4d87c747d/skills/verification-before-completion/SKILL.md).
