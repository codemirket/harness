## Recommended global layer

Use the authored [marketing-writing](../../skills/marketing-writing/SKILL.md) as the only new global marketing skill. It distills context reuse, concrete benefits with proof, customer vocabulary, clear next actions, fair comparisons, proportionate edits and draft-versus-publish boundaries. It avoids seven mandatory editing sweeps, simulated expert panels, unsupported conversion statistics, brand-specific ECC defaults, and tool/agent mandates.

Keep existing document/PDF/spreadsheet/presentation runtime skills as the global document layer. These three sources add no compelling generic document editor to justify duplicating that layer. ECC `nutrient-document-processing` is a vendor-specific API integration, not an interchangeable local document skill; it was inventory-screened only.

## Specific defects that change adoption decisions

- [Marketing A/B analysis](https://github.com/coreyhaines31/marketingskills/blob/dda3841f0b294e01e93b1541486beefbfab0915e/skills/ab-testing/SKILL.md) misinterprets p-values as the chance the result is random. The [ASA statement](https://www.amstat.org/docs/default-source/amstat-documents/p-valuestatement.pdf) explicitly rejects that interpretation. This needs correction before adoption.
- [Schema skill](https://github.com/coreyhaines31/marketingskills/blob/dda3841f0b294e01e93b1541486beefbfab0915e/skills/schema/SKILL.md) still associates WebSite with search boxes and lists HowTo for rich-result work. Google [retired sitelinks search boxes](https://developers.google.com/search/blog/2024/10/sitelinks-search-box) and [HowTo rich results](https://developers.google.com/search/blog/2023/08/howto-faq-changes). Valid schema markup is distinct from current Google eligibility.
- [ECC E2E skill](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/skills/e2e-testing/SKILL.md) fills/clicks before registering waits for the response, which can miss a fast response. [Playwright's official sequence](https://playwright.dev/docs/network) registers the promise first, performs the action, then awaits it.
- [ECC database migrations](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/skills/database-migrations/SKILL.md) combines useful expand/contract ideas with questionable examples and absolute rules: labels ALTER TABLE adding a nullable column as no lock; one early rename sequence backfills before dual writes; loop backfill can stall when source values remain NULL. Do not promote the examples as safe production recipes without dedicated database review. This file was fully read but is not selected.
- [ECC accessibility](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/skills/accessibility/SKILL.md) conflates visible focus with WCAG 2.2 SC 2.4.11 (Focus Not Obscured) and treats all native targets as 44pt. Prefer specialist UI source and verify actual standard/platform criteria; do not use this as a compliance certificate.

## Entire-plugin and automation concerns

- Marketing plugin manifests point to the complete `skills/` collection. Installing the marketplace plugin means 50 broad triggers. Select exact directories instead. Main selected prompt files contain no executables. The separate `tools/` integration ecosystem is not automatically trusted by selecting a prompt. [Partner policy](https://github.com/coreyhaines31/marketingskills/blob/dda3841f0b294e01e93b1541486beefbfab0915e/tools/PARTNERS.md) discloses paid placements and house tools; preserve disclosures if copying integration guides.
- ECC is an operating environment, not only a prompt library. The [Claude manifest](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/.claude-plugin/plugin.json) defaults hooks on; hook declarations cover PreToolUse, PostToolUse, compaction, start/end, stop, observations, quality tooling, cost tracking and notifications. The [Codex manifest](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/.codex-plugin/plugin.json) registers a session-start hook and `.mcp.json`, which launches `chrome-devtools-mcp@1.10.1` via npx. Those capabilities are unnecessary for a curated prompt registry. Do not copy `.claude-plugin`, `.codex-plugin`, hooks, rules, agents, installers, root instructions or MCP settings implicitly.
- Caveman [plugin hooks](https://github.com/JuliusBrussee/caveman/blob/99aafe151a1be72be783e662858e8a0955add59f/.claude-plugin/plugin.json) activate voice and track mode at session/prompt boundaries. Its [README](https://github.com/JuliusBrussee/caveman/blob/99aafe151a1be72be783e662858e8a0955add59f/README.md) distinguishes a local prompt skill from a CLI that sends usage telemetry by default. `caveman-setup` reroutes application LLM calls through a supplied gateway and can send provider keys in BYOK mode. `caveman-compress` calls Claude, backs up and overwrites prose files. These are separate products/data flows, not a minor style improvement.

## Portability

- Selected prompt-only directories are usable as knowledge on Codex and Claude, macOS and Windows; their content does not by itself require an interpreter. Project task tooling still depends on the actual language/runtime. Do not claim cross-platform runtime testing from Markdown review.
- Preserve full selected skill directory and internal references. Related Skills names are optional handoffs, not authority to install the entire source. References to a parent `rules/` or other absent skill must be surfaced or adapted; do not ship silently broken links.
- Use `.agents/skills/` for project Codex discovery and `.claude/skills/` for Claude according to the current supported harness. The registry should map location rather than copy source installers. Do not rely on Bash scripts on native Windows; native paths, quoting and executable detection belong to our installer.
- ECC tools frontmatter and Claude Agent/Task/Slash command examples are not portable API declarations. Detect available capabilities. Our catalog picker must not inherit source model pins, approval ceremonies, automatic delegation, fixed coverage thresholds or presumed provider connections.

## Catalog-picker techniques worth adapting

- Search local available capabilities first; choose a task match rather than keyword popularity. ECC skill-scout use/extend/build triage is useful, but local paths must include both harnesses and should not require a new user decision where the task already authorizes creation.
- Track provenance at immutable commit + directory + license; support `selected`, `adapt-first`, `deferred`, and `excluded` states. Installation must filter by selected status instead of making the entire repository a registry.
- Install the smallest compatible project selection. Record installed file digests, target scope and ownership so updates can preserve user changes and cleanup can remove only owned unchanged files.
- Keep review coverage honest. Store references read and unresolved risks alongside recommendation; do not convert source claims, stars, example eval fixtures, or benchmark headline numbers into measured quality for this user.
- Borrow only bounded retrieval and exact-payload preservation from Caveman. The existing global principles already require clarity and efficiency; a persistent compressed voice is unnecessary.
