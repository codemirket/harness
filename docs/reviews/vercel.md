## agent-browser installation contract

The [hidden stub](https://github.com/vercel-labs/agent-browser/blob/6d3e22c673a44271d0c213c2fef722e0aeba627d/skills/agent-browser/SKILL.md) loads runtime guides through `agent-browser skills get core` and other names. Copying it or adding the Claude marketplace entry does not install a browser or CLI. Its description explicitly prefers agent-browser over built-in tools, which conflicts with personal task-based selection. Host-specific Bash allowed-tools metadata is neither a Codex permission grant nor a reason to bypass approval policy.

Package 0.38.2 distributes native Rust binaries (macOS, Linux, Windows); Node >=24 is declared for npm lifecycle/wrapper, while an installed native executable runs without Node or Playwright. [postinstall.js](https://github.com/vercel-labs/agent-browser/blob/6d3e22c673a44271d0c213c2fef722e0aeba627d/scripts/postinstall.js) downloads the release platform binary without checking a release digest in that script, trusts an existing binary, logs download failure without necessarily failing npm install, and rewrites an existing global npm shim even when the package install is local. Windows ARM64 falls back to x64 in this distribution. A deterministic personal installer should separately pin package/native artifact identity and verified checksums, preserve unrelated global shims, install guides alongside the CLI, and verify `--version` and guide discovery. Do not silently execute this lifecycle as part of copying a skill.

`agent-browser install` fetches the current Chrome for Testing Stable manifest and stores browser files under `~/.agent-browser/browsers/chrome-<version>`; it does not pin a Chrome version to package 0.38.2. Linux `--with-deps` can invoke system package managers. Existing Chrome/CDP attachment avoids download but introduces user-profile ownership and CDP exposure concerns. Native runtime binary, guide data, browser version/path, MCP profiles and plugins are distinct installer records. `AGENT_BROWSER_SKILLS_DIR` affects guide lookup; install full matching skill-data, not only the stub. [Installer](https://github.com/vercel-labs/agent-browser/blob/6d3e22c673a44271d0c213c2fef722e0aeba627d/cli/src/install.rs), [guide lookup](https://github.com/vercel-labs/agent-browser/blob/6d3e22c673a44271d0c213c2fef722e0aeba627d/cli/src/skills.rs).

MCP is optional `agent-browser mcp` stdio, configured per host with deliberately selected profiles; debug/plugin capabilities can execute processes. Domain allowlists constrain browser traffic, not operating-system capabilities, and have unsupported attachment modes. External credential/browser-provider plugins are separate executable dependencies. Preserve existing host configuration and never infer authorization from tool availability.

Both fallback deployment scripts stage source and upload to a claimable service, excluding node_modules/.git/.env/.env.* but not honoring gitignore/vercelignore or other credential file patterns. HTTP 4xx is called ready and timeout still returns a deployment object, so URL emission is not deployment verification. Preserve the useful exact team/project targeting and preview intent in a newly authored deployment recipe.
