## Tool assignment and quality feedback

Workflow metadata remains the owner of eligible/required/verification tools and
specialist expertise. Every workflow default and declared alternative is checked:
selected expertise is delivered, required verification remains, and tools cannot
expand from role text. An explicitly chosen cross-domain lead still receives the
actual workflow specialist; this preserves useful multidisciplinary review.

Unknown tool names now fail before runtime activation. Owned policy metadata also
replaces a repeated tool-name allowlist for pre-dispatch receipts. The JavaScript
server dispatches only own handler properties, rejecting names such as `constructor`
and `__proto__` as unknown tools.

Completed renderers now attest completion separately from QA success. Negative QA
keeps hash-bound output available for inspection and repair instead of being
misclassified as an uncertain mutation. It still blocks completion until the failed
tool is corrected and current output verified. Handler exceptions without an owned
receipt remain uncertain; no mutation replay was added. A real protocol regression
renders a mismatching image, verifies saved bytes, corrects it and reaches a match.

Malformed or stale design reviews return bounded feedback instead of terminating
the run. Retries stay inside existing turn/deadline limits. Valid failed reviews
consume the same correction allowance, and exhausted budgets still reject success.
Final artifact hashes, target freezing, required tools, permissions, path isolation,
installer rollback, publication recovery and checkpoint budgets remain enforced.
These changes improve feedback consistency; they do not establish aesthetic gains.
