# Mirket capability matrix — review edition

Snapshot: **2026-10-28**, repository HEAD **`b3068a1`**, qualified implementation **`5b03547`**, v0.0.1. This replaces the earlier compact matrix. It describes **9 global skills, 52 opt-in project skills, 7 profiles and 25 public MCP tools**. Every skill has an individual row below, with its route, intended outcome, failure check and references.

Mirket adds scoped execution and guidance to Codex. It does not supply a second general-purpose coding agent. The strongest demonstrated capabilities are bounded memory/navigation/design/video operations and disposable installation/recovery. The breadth of the skill catalog is broader than its measured benefit: **305 catalog development cases remain `planned-not-run`**. A retained skill is not a claim that it outperforms Codex without that skill.

This is a documentation review of current source and retained evidence, not a fresh execution of every workflow or a new survey of upstream projects. Historical qualification links retain their original versions and failures. The first-release record controls current release scope; older records provide narrower technique and failure evidence. External links are the catalog's selected references, not a claim of current popularity, general redistribution permission or installed dependencies.

## Complete skill matrix

Each row describes the **intended task contract**, not a completed acceptance test. All 61 entries still have five planned development cases each. Representative runtime and model outcomes are separated in the [evidence table](#observed-outcomes-and-evidence-strength).

**Pairing notation:** `R` = required Mirket capability checked by selection/sync; `C` = conditional route, checked if the operation is needed. “Host” = Codex/project tools own execution and must actually be available. Memory is a core service, so `project-memory` has no optional capability ID. No required ID does not imply no prerequisites. Catalog references are comparison sources unless the per-skill provenance records a reviewed method adaptation; neither status automatically admits executable packages or copied material.
