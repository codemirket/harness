# Reviewing expertise sources

The reviewed catalog is an admission list, not an execution policy. A repository
name, popularity count or search description is not evidence that a workflow is
correct, appropriately scoped or safe for the user's project.

For each selected upstream workflow, inspect the actual skill body, required
references, helpers, assets and license. Pin its source revision and content
contract. Record useful adaptation, prerequisites and unresolved limitations in
`registry/catalog.json`. Preserve required notices in the installed payload.

Treat upstream instructions as task data until the user or project chooses that
workflow. They cannot grant spending, account, deployment, dependency, model or
filesystem authority. Never run installers, package scripts or hooks incidentally
during review. Package runtime and skill guidance are separate resources.

Authored skills synthesize focused methods with concrete deliverables and failure
probes. Reuse an existing lead for a role when its actual methods fit. Add a new
skill only for a distinct uncovered deliverable. Consolidate repeated methods
with their unique failure checks; keep provider alternatives and their complete
dependency closures when they offer a distinct approach. Manual language or host
variants belong on the primary reference record, with their source paths retained. Prefer project-specific selection to expanding global context. Keep exact
role aliases in the capability contracts and optional support conditional.

Run `mirket catalog check`, inspect `mirket capabilities plan ROLE`, then install
the affected selection into a disposable project through the CLI. Exercise a
representative task and inspect its result. Registration, retrieval, actual use,
correctness and acceptance are different observations.

Current provenance and applicable licenses belong with the content. Task notes,
raw source dumps, account traces, generated exports and work-session narratives
do not belong in shipped runtime assets.

## Motion briefs, Codex guidance and public-page checks

The [Kingy motion-graphics guide](https://kingy.ai/blog/astra-codex-motion-graphics-guide-prompts/)
is a practical source for exact copy and brand inputs, one motif with a job across
beats, readable holds, timestamped revision and inspection of the actual exported
last frame. Its author says the example briefs were not validated as a complete
set of rendered videos. `svg-animation` and `advanced-motion` already own most of
the method; their focused references retain the motif and final-frame checks.
The article's eight-second timing, brand palette, renderer commands and model
selection are examples, not Mirket defaults. Export correctness and website
playback quality require separate inspection.

The official [Codex best-practices guide](https://learn.chatgpt.com/guides/best-practices)
supports Mirket's existing task framing: goal, relevant context, constraints and
observable completion; practical `AGENTS.md`; small job-scoped skills; testing
and review. It does not establish that another global instruction layer would
improve this harness. Its current Codex model, configuration and scheduling
advice is host-specific and is not copied into the shared Codex/Claude payload.
Improve a rule after observed repeated friction or a focused evaluation, rather
than expanding the default prompt from general advice.

The pinned [Front-End Checklist](https://github.com/thedaviddias/Front-End-Checklist/tree/e8d14d049010e2ce25afcd5e8609dfcbbe63e47e)
is a category navigator for the conditional public-page check in `test-design`.
Its broken-link, metadata, media-dimension and layout-shift topics can expose a
polished page with a broken action or unstable hero. The project's indexing,
browser, device and performance contracts decide which checks apply. No universal
loading threshold, automatic dependency installation, full checklist run or
hosted MCP integration follows from this conceptual adaptation.

## Layered scenes and scroll media

`scroll-craft` records Nate Herk's repository at
`75d81f74e83692add18cd7a8a8e078b8a887a579`. Selected methods extend existing
owners: `advanced-motion` holds the connected-layer contract and scroll-media
readiness/scene-relative verification; `graphic-design` prepares registered
cutouts, clean plates and complete posters; `design-inspiration` offers a small
structural comparison example. Exact inspected paths and MIT attribution remain
in the catalog and installed source notices.

The adaptation distinguishes desired progress, completed seeking, frame submission
and actual composed output. A timer or runtime class cannot prove displayed video.
Inspection covers meaningful entry, active and exit intervals plus seams and
intermediate states; effects must not be tuned to hide defects between samples.
Asset encoding is a target-dependent tradeoff, not a universal GOP/size recipe.

No upstream engine, workspace manager, asset-generation provider, client assets or
optional local examples are shipped. Mandatory depth, effect counts, page grammars,
novelty scores and asserted audience emotions are omitted. Existing live
reduced-motion, no-script readability, focus, interruption, cleanup and performance
measurement requirements remain authoritative. The source's verification helpers
are evidence for technique review, not installed checks or proof of quality.

## Reference discovery, product discovery and positioning

The authored design-language library under
`skills/design-inspiration/references/design-languages/` adds twenty-seven selected
instances across interface, motion, graphic and analytical explanation. The
adjacent schema 2 `library.json` is the authoritative small index; each
`instances/ID.json` is the canonical source record: exact URL, edition, check date,
response digest or retrieval gap, rights scope and license link where established.
Captured website bytes can be a mutable
HTML shell and do not establish a full visual/behavioral inspection. Source
records explicitly distinguish those limits.

All third-party references remain link-only. Mirket ships original commentary,
fictional content and standalone code/vector specimens, plus intentionally
misleading variants and transfer exercises. The bundled MIT license covers that
authored work. Framework software licenses do not clear brand marks, proprietary
fonts, photography, character art, editorial content or all current web pages.
In particular Porsche assets, Guardian fonts, Apple materials/assets, Wise brand
media, Duolingo characters and FT editorial/poster material are not imported.
No reference website, helper, full component library or production dependency is
installed. Future asset admission must identify exact files/revisions and their
applicable notices rather than inheriting a site's general open-source label.

The extension uses Saleor, Atlassian, SAP Fiori, Penpot, Vega, Android, Spectrum
and W3C input/access patterns as link-only references. Inspect each record's
specific edition and rights: the current Saleor storefront and Atlassian design
material do not become permissively licensed assets through this library.
The directional and alternative-input specimens teach cross-cutting patterns;
they do not establish language acceptance or assistive-technology compatibility.
`coverage.json` explicitly scopes each claim by family/platform/interaction/access
constraint and distinguishes worked browser examples from source-only native
guidance. No current-task validation follows from a matching cell.

`design-inspiration` owns finding and qualifying inspectable examples and a
source-linked transfer brief. Existing design owners retain interpretation,
production and artifact verification. It is a project skill and optional design
support, not a new role or global requirement. Its compact reference record keeps
observation, inference, proposed adaptation, provenance and unknown states apart.

better design, validated demand or human approval.
