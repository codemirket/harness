# Design, illustration and motion source review

Reviewed 2026-10-10 for the personal Codex Desktop / Claude Desktop Code harness.
The accompanying [machine-readable review](design.json) records all nine sources,
revisions, inspected paths, decisions and applications. The revision/path links
below identify the actual reviewed bytes, not a moving default branch.

## Outcome and limits

Use an authored interface lead and an authored graphic-design lead, then select
bounded specialists for the actual deliverable. The strongest shared methods are
brief-derived composition, truthful content, semantic fidelity, plausible failure
fixtures and inspection of the working or exported result. No source justifies
one universal aesthetic or installing every specialist by default.

Eight collections contribute methods worth adapting. Remotion remains a manual
reference because no license for the skill repository was found at the reviewed
revision. Archify, Diagram Design, OpenDesign and Impeccable include executable
or packaging surfaces that need separate runtime review; their Markdown is not
the whole capability. A manifest entry cannot prove activation, correct use,
rendering, visual quality or user acceptance.

This was fresh primary-source static research. Public repository metadata and
source were fetched on the review date. Eight repositories were read from private
shallow clones. OpenDesign's 15,352-path tree was enumerated through GitHub, and
named files were fetched at the exact commit after a large clone was stopped.
No upstream source, installer, hook or renderer was executed; no upstream
dependency was installed. Deep relevant-path review is not every-line or
whole-runtime certification. The exact path inventory and partial-read limits
are recorded below. Temporary retrievals were removed after the report and
authored changes were retained.

## Integration decisions

| Source | Decision | Host/runtime boundary |
| --- | --- | --- |
| UI UX Pro Max | Adapt bounded retrieval and portable craft | Python helpers/data travel together; npm installer and client-path generation are separate |
| Hallmark | Adapt composition and relevant-state review | Full package assumes theme assets, project files and substantial process |
| Taste | Adapt selected methods; correct redesign contradictions | Plain skill text still carries framework, image-generation and install mandates |
| Archify | Adapt semantic fidelity; defer full runtime | Node/browser toolchain, update checks, cache writes and asset terms |
| Emil's skills | Adapt focused interaction/mobile/QA specialists | Examples require the actual framework and input model |
| Diagram Design | Adapt semantic and render evidence | Packaged Python checker differs from repository-only browser/export gates |
| OpenDesign | Adapt brief/trust/composition architecture | Full desktop/daemon runtime, Node/pnpm/native dependencies and postinstall |
| Impeccable | Adapt review triage; defer engine/hooks | Automatic lifecycle hooks and first-run binary retrieval/execution |
| Remotion | Defer redistribution; retain manual reference | Unverified skill license plus versioned video/browser/media dependencies |

Existing manual entries for Hallmark, Archify, Diagram Design, Impeccable and
Remotion should stay manual. Refreshing their source metadata is not permission
to run them. Full Taste and raster-concept siblings remain explicit reference
choices. The concrete installable defect found was `taste-redesign-skill`: a
truthfulness note left two opposite instructions in the body. The replacements
and expected hash below have now been recorded by integration in the registry.
Installed-copy verification remains part of the primary agent's integration work.

## 1. UI UX Pro Max

Revision: `50d8a7de0900119855614541f15a1a616691eb33`.

The useful idea is a bounded retrieval tool, not a style oracle. Its
[entry workflow](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/50d8a7de0900119855614541f15a1a616691eb33/.claude/skills/ui-ux-pro-max/SKILL.md)
chooses a dominant short query, distinguishes a design-system request from a
domain or stack lookup, and handles a failed match explicitly. The actual
[search implementation](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/50d8a7de0900119855614541f15a1a616691eb33/src/ui-ux-pro-max/scripts/core.py)
uses BM25 with bounded confidence/coverage behavior and a cache tied to fields,
version and file metadata. Stable CSV snapshots avoid reading a half-changing
dataset. The
[reasoning contract](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/50d8a7de0900119855614541f15a1a616691eb33/src/ui-ux-pro-max/scripts/reasoning_contract.py)
uses a closed grammar and rejects unsupported rule forms rather than evaluating
arbitrary expressions. These are useful harness engineering patterns.

The design dataset is less authoritative. The inspected initial rows of
[ui-reasoning.csv](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/50d8a7de0900119855614541f15a1a616691eb33/src/ui-ux-pro-max/data/ui-reasoning.csv)
associate categories with specific fashions, and some reasoning/confidence fields
are empty. Healthcare accessibility labels, luxury glass effects and SaaS visual
preferences are recommendations from the author, not measured user requirements.
The output should expose provenance and uncertainty instead of presenting a
retrieval match as validation. A small repair should not automatically trigger a
new design system.

The inspected Python route is standard-library based. Optional CLI initialization
uses a different Node/client-writing surface. Claude plugin-root substitution
and the Codex template's paths are not interchangeable. MIT permits reuse with
the license preserved, but the selected skill must carry its actual scripts,
data and references. Adopt short-query/abstention behavior if this helper is
enabled; keep the user's brief, real stack, brand and rendered evidence above its
ranked rows. Its atomic persistence pattern is worth reusing independently.

## 2. Hallmark

Revision: `13ac0ec7e148655948100b6396439e481361d690`.

The [workflow](https://github.com/Nutlope/hallmark/blob/13ac0ec7e148655948100b6396439e481361d690/skills/hallmark/SKILL.md)
usefully distinguishes a component from a full page and asks the agent to inspect
the current implementation. Its
[structure reference](https://github.com/Nutlope/hallmark/blob/13ac0ec7e148655948100b6396439e481361d690/skills/hallmark/references/structure.md)
offers genuine composition axes: content arrangement, heading relationship,
image treatment, rhythm and action placement. These can help a design emerge
from the brief instead of becoming a color swap of a generic page.

The authority hierarchy needs correction before adoption. Its
[slop-test gate 54](https://github.com/Nutlope/hallmark/blob/13ac0ec7e148655948100b6396439e481361d690/skills/hallmark/references/slop-test.md)
explicitly overrides requests to preserve a reference's heading structure.
Other gates universally forbid fonts, layouts and colors, or require a new
structural fingerprint because the previous output used one. Those preferences
can undermine an established brand or coherent campaign. Required questions,
stamps, logs and caches are heavy for a complete brief or routine repair, and
preflight cache validity is not proof that the current render was inspected.

The [state reference](https://github.com/Nutlope/hallmark/blob/13ac0ec7e148655948100b6396439e481361d690/skills/hallmark/references/interaction-and-states.md)
is valuable as a prompt to inspect neglected states, but every control does not
need all eight listed states. `aria-disabled` plus styling is not an actual
disabled interaction contract. Fixed modal focus and validation rules need
semantic context. APCA scores and WCAG contrast ratios should not be treated as
interchangeable conformance checks. The full MIT package also assumes token/theme
files outside the skill directory. Keep it manual; adapt content-led structural
decisions and relevant state checks without its universal style bans or ceremony.

## 3. Taste Skill

Revision: `717446e07a78d4e6d7918b1fde1a263378eebac9`.

The current [main skill](https://github.com/Leonxlnx/taste-skill/blob/717446e07a78d4e6d7918b1fde1a263378eebac9/skills/taste-skill/SKILL.md)
is explicitly for landing pages and portfolios. That narrower scope matters:
it should not become the default authority for dense applications, admin tables
or every mobile screen. It has useful brief inference, reference reading, existing
system awareness and direction-setting practices. Its detailed prescriptions
also contain fixed font/palette choices, mandatory imagery and motion, framework
assumptions, installation directives and a ban on handcrafted SVG. Those conflict
with a general personal harness and the requested graphic-design role.

The [mobile image sibling](https://github.com/Leonxlnx/taste-skill/blob/717446e07a78d4e6d7918b1fde1a263378eebac9/skills/imagegen-frontend-mobile/SKILL.md)
explicitly makes images only. Its multi-screen consistency and safe-area thinking
can inform concept work, but a phone mockup does not establish native navigation,
text accessibility, keyboard behavior or a functioning app. Default premium/iPhone
framing is a preference to change when the brief requires it. Real vector or
functional UI deliverables need a different production route.

The [redesign sibling](https://github.com/Leonxlnx/taste-skill/blob/717446e07a78d4e6d7918b1fde1a263378eebac9/skills/redesign-skill/SKILL.md)
contains instructions to make invented metrics look organic and randomize dates.
These contradict truthful content even though other portions favor realistic
work. The old installed pin had the same defect. An adaptation note did not
remove it; exact counted replacements do. Keep MIT notices, verify expected
source bytes/counts and fail closed if the payload changes. The shell indexer is
unnecessary for this selection and has Bash associative-array assumptions.

## 4. Archify

Revision: `54edef453ca3fc495f488c30de97eaea0c789f19`.

[Repository authoring](https://github.com/tt-a1i/archify/blob/54edef453ca3fc495f488c30de97eaea0c789f19/archify/references/repository-authoring.md)
is unusually useful: architecture comes from observed code paths, not component
names guessed from a directory listing. Reads, writes, orchestration and evidence
need distinct treatment. Credential-free origin and commit identity let a reader
trace a claim to source. The correct diagram type follows the question being
answered, rather than always producing a box-and-arrow architecture image.

The [layout repair guidance](https://github.com/tt-a1i/archify/blob/54edef453ca3fc495f488c30de97eaea0c789f19/archify/references/architecture-layout-repair.md)
preserves graph meaning while improving the main path, branches, stores, return
flows and routes. It is more dependable than arbitrary coordinate nudging or
deleting inconvenient relationships. Typed input, validation and artifact-bound
delivery receipts offer a useful separation between semantic source, rendered
output and proof. Keep these concepts in the graphic/diagram workflow.

The [delivery contract](https://github.com/tt-a1i/archify/blob/54edef453ca3fc495f488c30de97eaea0c789f19/archify/references/delivery-contract.md)
does not make perceptual inspection mandatory on all normal generation paths.
Our harness must still inspect the actual final-use image when promising visual
quality. Tiny projected text thresholds cannot stand in for destination-size
readability. The [update child](https://github.com/tt-a1i/archify/blob/54edef453ca3fc495f488c30de97eaea0c789f19/archify/scripts/delivery-update-child.mjs)
also demonstrates that delivery includes executable update/cache behavior.
Node/browser readiness and this network boundary require explicit setup.

MIT covers the core, while
[third-party notices](https://github.com/tt-a1i/archify/blob/54edef453ca3fc495f488c30de97eaea0c789f19/archify/THIRD_PARTY_NOTICES.md)
include fonts and marks with attribution, share-alike or noncommercial conditions.
Do not relabel the entire asset bundle MIT. Prefer simple semantic shapes unless
a specific mark improves comprehension and its rights are addressed.

## 5. Emil Kowalski's skills

Revision: `e8a175de22ae1e49370fc144c1f3bb9aeedf988d`.

The strongest addition to design QA is
[break-ui](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/break-ui/SKILL.md)
and its [fixture catalog](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/break-ui/CATALOG.md).
Use plausible data through the same schema or data boundary as production:
long text, missing fields, zero/one/many rows, large values, translations and RTL.
This exposes real layout failures without editing markup solely to manufacture
a screenshot. A development-only fixture selector plus a retained regression
fixture makes fixes repeatable.

[Animation review](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/review-animations/STANDARDS.md)
contributes useful questions about purpose, frequency, origin, release/press,
reversal and repeated input. Those matter more than adding motion everywhere.
[Mobile guidance](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/mobile-native/SKILL.md)
adds keyboard, viewport, safe-area and input details that a desktop screenshot
misses. The explicit-only prototype workflow is also a good activation pattern:
explore meaningful alternatives when requested, then integrate one and remove
the exploratory scaffolding.

Adapt rather than mechanically enforce. Absolute animation timing/property
rules conflict with some examples and with context. Transform names or a chosen
library do not guarantee acceleration or frame rate. Mobile apps can have hybrid
input; essential clipped content needs an accessible path beyond a hover tooltip.
The pause-before-fix convention must not override an already authorized repair.
MIT prose is portable, but code examples must fit the actual React/CSS/Expo stack.
Use these as narrow specialists selected by the interface lead, not a giant
always-loaded design prompt.

HTML description. MIT core and third-party icon/font notices need separate
treatment; a collection's permissive license does not establish trademark
permission for every depicted brand. Adapt semantic fidelity, accessible SVG and
render proof, while leaving its house typography, visual bans and first-use style
gate as explicit optional choices.

## 7. OpenDesign

Revision: `17e255959703a3fad7c8eb7f7b70dcafccc5629a`.

This is a full design product, not merely a folder of skills. The
[skill protocol](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/docs/skills-protocol.md)

such as `capabilities_required` is not an enforced permission boundary. Actual
plugin trust and grants live elsewhere. This directly informs harness design:
prove that the policy reaches the execution path used by each host, instead of
checking only that a document exists.

The [stage policy implementation](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/apps/daemon/src/plugins/strategy-stage-policy.ts)
uses known provenance/hash and a constrained owned shape before granting bundled
policy semantics. That is stronger than trusting arbitrary skill frontmatter.
The [trust implementation](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/apps/daemon/src/plugins/trust.ts)
also reveals expansive local-source defaults; a personal harness should not
consider arbitrary local content safe merely because it is on disk.

Useful design inputs include
[brief formation](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/skills/design-brief/SKILL.md)
and [reference contracts](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/skills/reference-design-contract/SKILL.md):
separate provided/observed/inferred facts, define keep/change boundaries and pass
enough context for the next artifact. Do not copy competing document templates:
the reference contract's fixed headings and current protocol are inconsistent.
The [state coverage rules](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/craft/state-coverage.md)
also overgeneralize timeouts, retries and focus changes; derive them from the
real data and interaction contract, especially for non-idempotent operations.

Named [design-review](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/skills/design-review/SKILL.md)
and [canvas-design](https://github.com/nexu-io/open-design/blob/17e255959703a3fad7c8eb7f7b70dcafccc5629a/skills/canvas-design/SKILL.md)
are chiefly activation/promotion wrappers. They cannot substitute for actual
design QA or graphic production capability. Root Apache-2.0 is not a license
audit of every mirrored skill. The package requests Node ~24, pnpm 10.33.x,
postinstall work and multiple native/workspace dependencies. Defer that runtime;
adapt the useful protocol/trust insights and original brief methods.

## 8. Impeccable

Revision: `d631a8827f99414d2b6daba4ef08b7f8701751d7`.

starts with task/state/flow failures, then system drift and local cosmetics.
That is a useful antidote to treating polish as extra decoration. Review packets,
target fingerprints and current-capture binding make critiques easier to assess.

runs work at SessionStart, PostToolUse for Edit/Write and Stop. Integrity checking
is useful, but does not itself authorize a new binary or persistent lifecycle
integration. Keep engine/hooks behind explicit setup and readiness review.

The [craft floor](https://github.com/pbakaus/impeccable/blob/d631a8827f99414d2b6daba4ef08b7f8701751d7/skill/reference/craft-floor.md)

mix useful distinct-composition thinking with exact aesthetic mandates,
multi-concept quotas and confirmation steps. Do not import those as universal
requirements. Package 4.5.2 declares Node >=22.18 and platform engine packages
0.1.14. Apache-2.0 and the third-party notices must travel with any reused payload.
The native playbook correctly needs native evidence; there is no HTML detector
that proves an iOS/Android layout behaves correctly.

## Authored harness changes and evaluation implications

The new [brief-to-proof reference](../../../skills/interface-design/references/brief-to-proof.md)
connects the actual brief to an information structure, purposeful composition,
relevant state/device cases and a repair/reinspection loop. It preserves facts
and distinguishes raster concept, working interface, automated checks, visual
inspection and user acceptance. `interface-design/SKILL.md` now routes meaningful
design and QA work to it. It does not require a second task record or a universal
font/layout choice.

The new [graphic-design lead](../../../skills/graphic-design/SKILL.md) covers visual
communication, type/hierarchy/composition, coherent asset families, rights and
native production selection. Its
[production reference](../../../skills/graphic-design/references/production-and-proof.md)
distinguishes raster, true vector, diagrams, plotting, editable documents and
motion. It requires use-size inspection and truthful screen/print limitations,
including actual printer profiles and physical proof when needed. It uses
available imagegen for raster work and never calls a bitmap-in-SVG a vector.
This is original guidance informed by the methods above, not copied vendor prose.

Representative evaluation probes for integration are:

- A narrow comparison screen with long real offers, missing optional details and
  one failed load; select only relevant states and complete the main task.
- A brand-constrained page using a font/color an upstream skill bans; preserve
  the valid brief and critique actual hierarchy, contrast and composition.
- A mobile flow with keyboard obstruction, back navigation and reduced motion;
  identify which claims require native/device evidence.
- A campaign family with an editable vector mark and raster illustration; export
  multiple aspect ratios and inspect each crop at use size.
- A diagram with a consequential conditional edge; improve readability without
  deleting or reversing that relationship.
- A print request missing its provider profile; produce a useful described proof
  without claiming press readiness from a generic RGB preview.

Five Markdown files passed the harness workbench's structure/local-link checks;
the JSON parsed with nine entries and all 94 current-revision inspected paths
were verified against the retrieved trees. Local Markdown-to-HTML previews were
inspected for report hierarchy, tables and the authored workflow sections. The
skill-creator quick validator could not run because PyYAML is absent from both
the system and bundled Python; no dependency was installed. The simple skill
metadata was checked directly. No representative product or graphic artifact
was created by this review alone, so it does not claim those role behaviors have
passed a live delivery evaluation.
