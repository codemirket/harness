## Trust-write attribution, restoration and continuation

The real config hash changed during CLI startup:

- Before: `7cf4d5f11d2a6593a35df91b3fa347638bc614ab3c165c231f1e51e613898317`.
- After: `eace3607099934e892acc4abb56d6bf7c83ca6d6c0138c7e74844259a5503ac9`.
- The entire byte difference is one new `[projects."…/model-creative/project"]`
  section containing `trust_level = "trusted"`. Removing only that exact section
  **in memory** reconstructs the exact pre-turn SHA-256.

The config mtime was 106 milliseconds after request creation and about 36
seconds before the SVG source write. No observed model command accessed the real
config. This precisely attributes the changed bytes to the task's CLI startup
trust entry, rather than an SVG instruction or an unrelated settings change.
The guard stopped live turns while this was investigated. On explicit direction,
restoration required the whole current config hash to equal the observed
post-turn hash, removed only the attributed section, preserved mode `0600`, and
verified the exact original pre-turn hash. No unrelated config bytes changed.

A further preflight used fresh unauthenticated `HOME` and `CODEX_HOME`, a minimal
environment without inherited provider credentials, a disposable Git project and
`--skip-git-repo-check`. The real config stayed byte-identical, but the CLI still
added a trust section in that disposable `CODEX_HOME`. The attempted turn exited
one after 18.378 seconds with missing-authentication HTTP 401 responses and no
generated model answer or tool work. The local trust write remains fixture
evidence; this flag is not established as a way to prevent Git-project trust
persistence. No credential bytes were copied to enable the preflight.

The authorized continuation therefore reused the previously observed non-Git
route, rather than pre-adding a live trust entry or copying credentials. The
remaining three actual model turns each preserved the real config's original
SHA-256. Its final hash again equals
`7cf4d5f11d2a6593a35df91b3fa347638bc614ab3c165c231f1e51e613898317`.
This is observed config preservation for those invocations, not an enforcement
guarantee that future CLI commands cannot write user state.
