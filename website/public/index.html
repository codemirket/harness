A working method for your coding agent.

Mirket is a local harness that gives your agent focused expertise, tools for specific tasks, and records of what was checked. Use it to bring a repeatable workflow to development, design and research.

01 / UNDERSTAND THE ROLE

Your agent does the work.
Mirket helps structure it.

A harness is the supporting layer around an agent. Mirket connects to Codex or Claude through MCP, the protocol agents use to access tools, and installs guidance the agent can read when it needs it.

You decide
The outcome, project rules, provider choices and permissions.
Your agent acts
Reads the code, reasons about changes, edits files, runs tools and explains the result.
Mirket supplies
Relevant methods and references, optional scoped workers, and records that connect the work to its verification.

Choose useful expertise

Discover focused skills for the task: API design, debugging, interfaces, research and more. Read what helps; keep the project’s own instructions in charge.

Delegate bounded work

When independent work helps, route Mirket-owned workers to available models with tools scoped to their assignment. The main agent integrates the result.

Keep work resumable

Optional task records retain decisions, progress and evidence for longer work. Add the agent runtime for explicit project memory and durable worker checkpoints.

Make verification explicit

Guidance calls for real tests and inspected outputs. Tracked completion checks catch missing or changed evidence; the agent still has to judge the result.

02 / GET STARTED

Install once. Set up each project.

You need Codex Desktop or Claude Desktop Code with local file and terminal access. The core harness is one executable; optional packages can wait until you need them.

1. Ask your agent to install Mirket

Paste this prompt into your agent. It follows the official guide, checks your device and verifies the release before running setup.

Paste into Codex or Claude
Open plain text

Read the prompt before running it in your agent.

Prefer a manual install? Download, verify and set up the binary. Check supported targets before installing optional packages.

2. Confirm the agent can use it

Start a fresh host session if needed. Ask the agent to invoke Mirket’s runtime_status tool. mirket doctor checks installation; a successful tool call in your host confirms that connection is active.

3. Choose expertise for your project

Open the project in your agent and ask:

Inspect this project and its instructions. Use Mirket to select and install the expertise relevant to its stack and current work. Preserve existing selections and edits, verify project health, and explain what you selected. Do not change application behavior as part of setup.

Prefer the CLI? Set up a project explicitly

Replace the absolute path and choose a capability that matches your work. This example selects both hosts and backend engineering guidance.

mirket project init --project /absolute/project --target all
mirket project add --project /absolute/project --profile project-foundation
mirket project add --project /absolute/project --capability "Backend Engineer"
mirket project plan --project /absolute/project
mirket project sync --project /absolute/project
mirket project doctor --project /absolute/project

init records the target hosts; add selects guidance; sync installs it. Selections live in .mirket/project.json. Use portable-foundation when the hosts have no shared global guidance.

03 / EVERYDAY USE

Describe the outcome. Ask for evidence.

Keep working in your usual agent conversation. You can name Mirket when you want a specific method. Routine changes can stay direct; delegation and durable tracking are useful when the task needs them.

Fix a bug or add a feature

Use Mirket’s relevant engineering guidance to fix this failing checkout. Find the cause, make the smallest complete change, and run the project checks. Explain what changed and what remains untested.

Expected result: an implementation, checks that exercise the affected behavior, and a clear account of any remaining limits.

Build or refine an interface

Use Mirket’s visual workflow for this settings screen. Inspect the existing screen or a minimal native specimen first. Build editable components, check desktop and mobile layouts, and test keyboard use and error states.

Expected result: a working interface and inspected renders compared with the starting target. Full visual workflow ↗

What gets checked in visual work?
Composition
Hierarchy, spacing and proportions.
Typography
Fonts, wrapping and readability.
Assets
Source rights, sharpness and fit.
Responsive layout
Reflow and reachable controls.
Behavior
Actions, keyboard access and states.
Motion
Playback and reduced motion, when needed.

A supplied reference or an inspected native specimen can establish the target. Mirket provides rendering tools; image generation, when needed, comes from the host.

Mirket-owned design workers enforce ordered reviews and evidence freshness. One target repair is allowed. Final repairs share a limit: static work gets 15 minutes/two repairs; interfaces and paged work 30 minutes/three; motion 45 minutes/four. Combined work uses the largest limit. Native host tools follow this as guidance. Passing a gate does not establish human approval.

Continue a larger task

Use a Mirket task record for this migration. Keep the decisions, remaining work and verification evidence together so we can resume. Delegate only independent pieces that help, and integrate their results before checking completion.

Expected result: recoverable progress tied to the project. Reuse an existing sufficient task record. How task evidence works ↗

04 / ARCHITECTURE

One local core. Two ways to use it.

The mirket command and local MCP server share the same Rust implementation. You use the CLI for setup and project management; your agent uses MCP tools to discover guidance and work with task state.

Guidance
The embedded catalog contains roles, skills and references. Setup installs shared guidance; project sync adds your selected specialties.
Project state
.mirket/project.json records project selections. The local Mirket home holds installation receipts, registered tools and a SQLite task database.
Worker routing
Mirket discovers available targets and models, resolves a bounded assignment, and dispatches only its assigned tools. Native host subagents remain outside this routing boundary.
Optional runtimes
Separate packages add design production tools or project memory and durable checkpoints. The core works without either.

Your host keeps control. Keep your existing agent and authentication. Local harness state does not mean local inference: configured models may be remote, with their own usage limits and billing. Mirket does not grant permissions or provide an operating-system sandbox.

05 / ADD ONLY WHAT YOU NEED

Optional packages

Both packages require a supported private Podman environment with Linux ARM64 containers. A supported core CLI does not automatically mean your device can run these packages.

Design: produce and inspect visual work

Browser checks with Playwright, editable files with Penpot, tokens with Style Dictionary, and tools for diagrams, video, documents, vectors and image processing.

Design package setup and tools ↗

Agent runtime: memory and recovery

The optional agent runtime uses Mem0 for explicitly chosen project facts and LangGraph for durable worker checkpoints. Local recall needs no hosted memory account or inference credentials. Chat history is not automatically ingested.

Durable-state backups cover records, memory and checkpoints. Project files, credentials and desktop settings need separate backups.

06 / KEEP THIS HANDY

Quick reference

mirket doctor          # Check your installation
mirket catalog search debugging
mirket update --check  # Check for a release
mirket update          # Update using saved setup choices

Project skill updates stay explicit: run mirket project sync --project /absolute/project for the project you intend to update. Inspect conflicting managed edits before retrying.

What changes on my device?

Setup installs a managed executable, shared instructions, skills and MCP configuration for your selected hosts. It preserves unrelated settings and stops on conflicting managed edits. A fresh unattended setup installs no optional packages.

Does Mirket guarantee correct results?

No. It supplies methods, scoped tools and inspectable evidence. Records and hashes can detect missing or changed artifacts; real tests, artifact inspection and human judgment determine whether the work is right.
