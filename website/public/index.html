VISUAL WORKFLOW

Start with a target.
Finish with evidence.

For new visual work and substantial redesign. An approved existing screen can guide a focused repair.

Read the workflow ↗
01

Inspect the target first.

Use your supplied reference, an inspected native specimen, or a host-generated composition suited to the medium. Inspect the hierarchy, type and focal asset. Freeze that target before implementation.

02

Build editable code.

Turn the target into real components, responsive layout and working controls. Keep exact copy and logos in the source. A screenshot stretched across the page is not a working interface.

03

Render and compare.

Inspect current output against the frozen target at matching content, viewport and state. Check narrow and wide layouts and exercise the interactions. Record specific defects and corrections.

NATIVE SPECIMENS

Compose in code. Inspect before expanding.

When the medium fits, the agent builds one minimal DOM, SVG, pixel, diagram, typeset or editor specimen, then renders and inspects it. That first passing render becomes the target. The same quality gates and limits apply.

No new image provider or model change is required. Mirket supplies production tools; image generation, when available, belongs to your host.

QUALITY GATES

Six checks.
A bounded review.

Each check gets an outcome and located observations. Missing, stale or failed required evidence blocks a Mirket-owned worker from completing.

Composition
Hierarchy, spacing, proportions and crop.
Typography
Actual fonts, wrapping, legibility and contrast.
Assets
Source rights, sharpness and fit in the composition.
Responsive layout
Narrow and wide reflow, clipping and reachable controls.
Behavior
Primary actions, keyboard focus and relevant states.
Motion
Requested playback, interruption and reduced motion.

Working UI must pass responsive and behavior checks. Animated work must pass motion checks.

One target repair. Static work: 15 minutes and two final repairs. Interfaces and paged work: 30 minutes and three. Motion: 45 minutes and four. Combined work shares the largest limit. At the limit, preserve the output and report remaining defects. New workers or extra variants do not reset the budget.

Mirket-owned workers enforce review order, evidence freshness and these bounds. Native host tools follow the same workflow through guidance. Agent observations remain judgments; a passing gate is not an aesthetic guarantee or human approval.

GOOD TO KNOW

Fits your environment.

What changes on my device?

Setup installs a managed Mirket executable, shared instructions, skills and local MCP connections for the hosts you select. It preserves unrelated configuration and stops on conflicting managed edits. Start a fresh host session to load the new tools.

Where does memory live?

Optional Mem0 memory and LangGraph checkpoints live in a contained local runtime with no network or provider credentials. Facts are explicitly chosen; chat history is not automatically ingested. Your agent’s inference still uses its configured provider. The memory package is Linux ARM64 only.

Can I use it with an existing project?

Yes. Your agent can inspect the project and select useful expertise. Project setup records those selections and installs their guidance. Installing Mirket does not automatically rewrite application code.

Does it replace my agent or subscription?

No. Keep Codex or Claude and your existing authentication. The harness and task state run locally; inference uses your configured providers, which may be remote. Their usage limits and billing still apply.

Does it guarantee better results?

No harness can guarantee correctness. Mirket makes guidance, tool scope and evidence explicit. Its checks can validate records and file identity; real tests and human judgment still determine whether the work is right.
