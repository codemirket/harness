# Independent capability review

Reviewed **2026-10-24**. Scope: agent-facing capabilities, memory/context, guide discovery and composition, verification, and public skill resources. This is a source review and a set of recommendations, not approval to implement, install, copy upstream content, or change the selected catalog.

## Executive verdict

**Keep the architecture and the complete 0.0.1 scope. Strengthen the agent-facing contracts before implementing their interfaces.** The plan has unusually strong ownership, preservation, platform, memory-lifecycle and artifact-verification requirements. The remaining capability risk is that a technically complete collection of engines can still be difficult for either host agent to discover, operate and verify. “An engine ran” and “the agent reliably completed the intended work” need separate acceptance evidence.

The most valuable changes are:

1. Make guide discovery, exact invocation and focused reference loading a portable, release-bound contract; test the first guide/tool journeys during M0/M1 rather than discovering interface mistakes in M4.
2. Specify source expansion, answerability and mandatory-constraint overflow in recall. Evaluate retrieval **and the decisions made from retrieved context**.
3. Define the browser’s observation/action loop, stale-target behavior and post-action evidence. Playwright availability alone does not specify an agent-usable browser.
4. Evaluate guides against a no-guide or previous-guide baseline, including false activations and mixed-boundary tasks.
5. Make the source-to-guide mapping concrete enough to exclude restrictive material and incompatible workflow machinery. The present named-source families are useful discovery leads, not an adequate authoring specification.

These mostly require small schemas, documentation, fixtures and measured host journeys. They do not require a VM, a Mirket model, a new framework stack, a general plugin loader, an agent scheduler, or more interchangeable engines. They are needed because 0.0.1 is intended to be fully capable, not because it is an MVP.

I inspected the implementation plan and references, the capability/memory/skill and ownership portions of the proposal and decisions, and relevant toolchain recommendations. Installer, PDF-engine and language-runtime qualification are adjacent reviews, not independently benchmarked here.

Evidence labels below mean:

- **Source-observed:** inspected current primary documentation, repository metadata, or actual skill instructions. This establishes what the source says, not runtime performance.
- **Inferred:** a design recommendation or expected benefit for Mirket. It must be tested after approval.

Research used official documentation and GitHub repository metadata/trees/raw files. Queries included Agent Skills specification/evaluation, agent tool ergonomics/context engineering, Trail of Bits security skills, Vercel agent skills/browser snapshots, QMD retrieval, Pi skills/compaction, Hermes memory/skills, scientific statistical-analysis skills, and W3C accessibility. ## Prioritized findings

### C1 — P1: Define the guide/tool entry contract before broad adapter expansion

**Plan:** `implementation-plan.md:124`, `implementation-plan.md:142–159`; `proposal.md:301–320`.

The plan commits to discovery, short entry documents and focused references, but leaves the actual host-visible selection/loading contract unspecified. That is appropriate authoring work in part; however, whether a host can find and invoke the right capability is an M1 interface decision. Twelve broad names such as “Engineering” and “Research and context” do not themselves expose narrower techniques such as SQL schema binding, statistical test selection or document redlining.

**Recommended minimum:** use ordinary portable `SKILL.md` packages for authored guidance, with concise descriptions, compatibility information, exact IDs and relative references. Whether a client receives those through its supported native skill surface or a Mirket read tool is an integration choice; avoid delivering the same full body through both. Expose a compact catalog/search response containing ID, purpose, when/when-not applicable, compatible operation/format, release identity and a focused read route. Exact-ID selection must work without a semantic search. A tool’s examples and guide references must correspond to the **installed release**, with missing/unavailable operations reported honestly. This is a finite catalog, not an extensible plugin framework or model router.

The [Agent Skills specification](https://agentskills.io/specification) describes metadata/body/reference disclosure and compatibility metadata. Pi’s [actual skills implementation documentation](https://github.com/earendil-works/pi/blob/f321e5bdd26b3624bfb2ab182a334d0a5edb698a/packages/coding-agent/docs/skills.md) shows why host differences matter: malformed skills, name collisions and explicit invocation have concrete behavior. Neither implies identical Codex/Claude behavior. The current [agent-browser skill entry](https://github.com/vercel-labs/agent-browser/blob/372ac5ce20fab885dbf45ee0c9d510ec8c3b6fdb/skills/agent-browser/SKILL.md) retrieves detailed instructions from its installed CLI version; that release-matching technique is useful even though its install commands and global-tool preference are unsuitable here. **Source-observed; Mirket benefit inferred.**

**Cost/value:** low-to-medium interface and fixture work; replaces ambiguous discovery and repeated broad guide reads. Start with three representative guides in M0/M1, then complete all twelve in M4. Do not implement a new tool-search model or a universal `execute(anything)` endpoint.

**Discriminating test:** two clients receive “fix this SQL reference,” “check whether these groups differ,” and “change one word in this text.” The first two reach the correct focused guidance and real tool; the trivial edit bypasses irrelevant guides. Exact invocation works offline. A deliberately mismatched guide release cannot advertise an operation absent from the installed adapter. Record loaded bytes, selection errors and output correctness.

### C2 — P1: Specify evidence expansion and distinguish missing evidence from incomplete retrieval

**Plan:** `implementation-plan.md:41`, `implementation-plan.md:67`, `implementation-plan.md:130–132`; `proposal.md:517–522`.

The plan already calls for bounded source-linked results, focused reads, source validity, hybrid ranking and direct fetching of critical constraints. Preserve those. The gap is the observable behavior when the answer requires evidence outside the first result budget, when a source changed or disappeared, or when applicable critical constraints themselves exceed the budget. “Twenty excerpts / 32 KiB” is an output default, not proof that an agent can safely answer.

**Recommended minimum:** separate search candidates from an expandable evidence read. Each hit needs a stable record/source identity, source revision or capture identity, a locator, scope, current/historical/conflicted status, and explicit expansion/coverage information. Reads should support ranges and bounded batches. Use existing source files or extraction artifacts rather than copying every source into durable factual memory. Distinguish `no_matching_evidence`, `index_incomplete`, `source_unavailable_or_changed`, and `budget_truncated`; provide the next useful action. Critical-constraint overflow must be visible as incomplete coverage, not silently ranked away. A host-authored query can include exact anchors and semantic phrasing; any hypothetical expansion remains a query, never a saved fact.

The inspected [QMD skill](https://github.com/tobi/qmd/blob/86d2365d17fc682e491c2c53d1e4a884aee8682a/skills/qmd/SKILL.md) separates candidate search from source retrieval, uses line-range/batch reads, and encourages the host agent to express lexical/semantic intent. This is useful without adopting QMD’s runtime or generative expansion. Anthropic’s [context-engineering discussion](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) supports retaining lightweight references and retrieving detail when needed. **Source-observed; Mirket design inferred.**

**Cost/value:** medium work inside the already-selected memory/source contracts; replaces whole-document dumps and repeated broad searches. Do not add a second knowledge database or index all files automatically. An on-demand document-collection index is a separate candidate only if reviewed tasks demonstrate that existing navigation, extraction, exact search and bounded source reads are inadequate.

**Discriminating test:** hide the decisive exception immediately outside the initial excerpt; the agent must expand it before concluding. Change the source after retrieval; expansion must reveal the mismatch. Fill the budget with relevant constraints and verify explicit incomplete coverage. An unanswerable query must not produce a supported-looking answer from a merely similar record.

### C3 — P1: Define an agent-usable browser observation/action contract

**Plan:** `implementation-plan.md:44`, `implementation-plan.md:87`, `implementation-plan.md:113`, `implementation-plan.md:136`; `decisions.md:50–54`.

The browser scope includes navigation, extraction, screenshots and permitted interaction. The plan does not yet say how an agent observes actionable elements, binds an action to a tab/frame/session, notices a stale observation, or verifies what happened. A launch-and-screenshot fixture can pass while ordinary agent interaction remains unreliable.

**Recommended minimum:** readable structured observations with scoped element identity or precise supported locators, focused snapshots, explicit tab/frame ownership, screenshot access, and observable action results. Re-observe after meaningful page changes; reject stale/missing targets rather than resolving the same ordinal against a new page. Separate accessible interaction state from article/content extraction—Readability is not an interaction tree. Include dialogs, file upload/download and new-tab outcomes if these are advertised operations. Preserve the plan’s rule against replaying an uncertain external effect; a timeout is not evidence that a submit failed.

Current [Playwright MCP snapshot documentation](https://github.com/microsoft/playwright.dev/blob/main/mcp/snapshots.mdx) describes actionable refs and explicit stale-ref errors. [agent-browser snapshots](https://agent-browser.dev/snapshots) additionally demonstrate compact/depth/selector filtering and a documented ref lifetime. These are strategies to implement through the chosen browser owner, not reasons to ship two browser-control stacks. **Source-observed; no browser workflow tested.**

**Cost/value:** medium adapter contract work already required by “browsing and automation”; replaces guessed selectors, excessive snapshots and misleading completion claims. Add one actual host-agent interaction journey to M0, not just library-level browser calls.

**Discriminating test:** a local app replaces a button after observation and contains two identically named buttons in different frames. A stale target must not click the replacement or wrong frame. Submit triggers a visible result but delays the response past timeout; the next step inspects state without resubmitting. The test passes only if exactly one submission occurred and the host reports the observed outcome.

### C4 — P1: Guide quality needs comparative and negative-trigger evaluation

**Plan:** `implementation-plan.md:132`, `implementation-plan.md:142–159`; `decisions.md:659`.

Representative guide-selection/output tests are already required. Add a stronger criterion: does the guide improve the work over the same host with no guide or the previous guide? A test that only proves a guide loaded can reward needless bureaucracy. A result that “looks thorough” can hide incorrect facts, wrong tests or repeated confirmation requests.

**Recommended minimum:** keep a small versioned evaluation set for each guide, with realistic prompts, expected artifacts/decisions and failure cases. Separately evaluate activation and task execution. Include near-match nontriggers, user overrides, absent tools, interrupted continuation, and combinations such as analysis-plus-spreadsheet or engineering-plus-security. Use clean host sessions, record host/model/client versions, and compare outputs, unnecessary calls/questions, context size and time. Keep held-out cases; repeat variable cases. Verification should inspect resulting artifacts/state, not merely ask the same agent whether it followed the instructions. This is a development test suite; host clients still own execution and any model access.

The selected [Anthropic skill-creator](https://github.com/anthropics/skills/blob/dbd4588f9e1033efb41dad4bef2f7947c8993d44/skills/skill-creator/SKILL.md) contains with/without comparisons, trigger/nontrigger sets and optional blinded review. The public [output-quality evaluation guide](https://agentskills.io/skill-creation/evaluating-skills) and [description evaluation guide](https://agentskills.io/skill-creation/optimizing-descriptions) separate these concerns. Use the method, not its automatic provider-calling scripts. **Source-observed; no claimed quality gain.**

**Cost/value:** moderate fixture/review work, no production runtime. Start with two or three cases per guide and expand based on failures; this is an initial sampling method, not a waiver of coverage. Keep the plan’s 100-query memory evaluation, but add answerability and downstream decision correctness to retrieval relevance.

**Discriminating test:** a candidate guide scores better on its examples but causes unnecessary planning/approval loops on trivial requests and misclassifies a held-out near-match. It must not be promoted solely for the higher training score. A guide that adds no demonstrated value should be shortened or rewritten while retaining its required expertise boundary.

### C5 — P1: Turn source-family mappings into explicit technique and rights decisions

**Plan:** `implementation-plan.md:142–159`; `proposal.md:320–324`; `references.md:6`, `references.md:105–112`.

The plan correctly requires exact source review and fresh authoring. Current sources show why this gate needs a concrete output before text is adapted: a source can be public, selected and actively maintained while particular material is unsuitable for redistribution or for Mirket’s ownership model.

Examples observed in actual bodies:

- Anthropic’s DOCX skill is marked proprietary. Its [license at the already-selected pin](https://github.com/anthropics/skills/blob/683bc88e56f3e09ba94f7055977f3d3aa499f202/skills/docx/LICENSE.txt) contains explicit restrictions on copying, derivatives and distribution. The current file retains those terms. Treat this material as link-only unless separate permission is established; independently derive Office methods from approved libraries and format documentation. This is a source-admission finding, not legal advice or a claim that the plan has already infringed anything.
- [Superpowers’ entry skill](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/using-superpowers/SKILL.md) demands very broad activation before ordinary responses. Its [verification skill](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/verification-before-completion/SKILL.md) has useful evidence checks but also a fresh-command-in-this-message rule. Mirket should verify evidence affected by changes, not rerun unchanged expensive checks mechanically.
- Current [Impeccable](https://github.com/pbakaus/impeccable/blob/936867543ac2576920d663cc9803597f6044f3ac/.agents/skills/impeccable/SKILL.md) begins with a helper launcher that may download a binary on first use. Its visual inspection and task-specific playbooks are useful; incidental bootstrap execution conflicts with the selected distribution policy.
- [gstack context restore](https://github.com/garrytan/gstack/blob/00100f1598dcfc192f0f0f2d3345b6825737932a/context-restore/SKILL.md) contains helpful provenance-sensitive continuation, but also substantial lifecycle scaffolding and project identity based on canonical remote with root fallback. Mirket explicitly must not merge independent clones by remote identity.

**Recommended minimum:** for each adapted section record source commit, exact file/section, technique retained, terms, dependencies/host assumptions removed, and the Mirket acceptance case. Label each source portion `adaptable`, `link-only`, `comparison-only`, or `rejected-for-this-use`. Keep the approved 52-source selection intact; recommend role changes rather than silently deleting sources or importing their ecosystems.

**Cost/value:** low authoring/release metadata; prevents incompatible defaults and accidental dependencies. This is not a new catalog service.

**Discriminating test:** a source update changes a skill’s helper invocation, license or host assumptions. The release cannot silently substitute the new body. A document guide remains fully usable offline without proprietary copied prompts or an upstream first-use installer.

### C6 — P2: Make task continuation useful without reproducing a host transcript system

**Plan:** `implementation-plan.md:41`, `implementation-plan.md:130`; `proposal.md:483–485`, `proposal.md:521–522`.

Compact task state is already selected, but its minimum useful fields and authority on resume are not explicit. Define a host-curated continuation record: objective, current user constraints, selected project/checkout, source/artifact pointers, completed work with observed evidence, unresolved questions, next actions and effects whose outcome is unknown. Separate verified findings, assumptions and proposed steps. Recheck source/revision applicability on resume. Prefer links to existing plans over duplicated prose.

The small [Matt handoff skill](https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/productivity/handoff/SKILL.md) contributes nonduplication and focused next-session context. Pi’s [compaction documentation](https://github.com/earendil-works/pi/blob/f321e5bdd26b3624bfb2ab182a334d0a5edb698a/packages/coding-agent/docs/compaction.md) illustrates structured summaries/file tracking, but those mechanisms belong to a host-owned session. Hermes distinguishes [procedural skills from factual memory](https://github.com/NousResearch/hermes-agent/blob/4dcef215cfe41bd2d02c2d1dad6e257a18101216/website/docs/guides/work-with-skills.md); adopt that distinction, not its automatic session storage or prompt injection. **Source-observed; recommendation inferred.**

**Cost/value:** small schema/template refinement within M2. It replaces repeated rediscovery while avoiding a second journal. A learned project technique should remain a source-backed note or host-authored project document unless the user explicitly asks to create/change a skill; no self-modifying installed guidance.

**Discriminating test:** resume in another host after the source branch changed and a prior submission timed out. The host identifies stale evidence and the unknown external effect, inspects current state, and does not repeat the submission or infer old permission from memory.

### C7 — P2: Balance specialist depth against the catalog’s strong visual emphasis

**Plan:** `implementation-plan.md:144–157`; `proposal.md:305–315`; `references.md:49–101`.

Groups C/E/G account for 29 of the 52 unique selected sources. That is appropriate to the user’s design ambitions, but source count does not establish equivalent depth for security, statistics, accessibility or data validity. The Data and analysis guide currently points to three broad vendor repositories, not a reviewed statistical method. “Beautiful artifact with wrong inference” remains a concrete failure mode.

**Recommended minimum:** use the focused additions ranked below to fill method gaps, not enlarge the twelve-guide list. Prioritize statistical design/effect/uncertainty reasoning, property/state-invariant testing, and explicit accessibility checks. Existing selected OpenAI threat-model guidance and Anthropic skill-evaluation guidance already provide useful depth; map those precisely before adding alternatives.

The inspected [statistical-analysis skill](https://github.com/K-Dense-AI/scientific-agent-skills/blob/593377bb048752abb0152deab9fbb1083a6087df/skills/statistical-analysis/SKILL.md) emphasizes design, dependence, effect sizes, missingness and distinguishing exploration from confirmation. The inspected [property-testing skill](https://github.com/trailofbits/skills/blob/196a9073ab10d35bacf111f945e02c00b2c6883a/plugins/property-based-testing/skills/property-based-testing/SKILL.md) distinguishes meaningful invariants from tautological/vacuous tests. [WCAG 2.2’s quick reference](https://www.w3.org/WAI/WCAG22/quickref/) provides criterion-linked interaction checks beyond visual polish. **Source-observed; no scientific-package versions or tests qualified.**

**Cost/value:** low-to-medium authoring and fixtures, no required new production libraries. Use existing project toolchains for calculations/tests. Add dependencies only when the project’s chosen task requires them and normal approval covers them.

**Discriminating test:** an apparently significant comparison with repeated observations must not be analyzed as independent samples without qualification. A parser test suite that only proves “no crash” must not be described as round-trip correctness. A visually polished form with an inaccessible keyboard sequence must fail the UI review.

### C8 — P2: Treat tool descriptions, result shape and errors as product behavior

**Plan:** `implementation-plan.md:124`, `implementation-plan.md:126`, `implementation-plan.md:159`.

Typed bounded result envelopes are already planned. Add task-focused examples and actionable errors: describe what an operation accomplishes, its side effects, prerequisites and how to continue after incomplete results. Prefer concise summaries with source/artifact expansion over duplicated full text and raw backend dumps. Measure startup metadata and results on both hosts; twelve guide descriptions are inexpensive compared with a large unbounded tool schema surface.

Anthropic’s [tool-design article](https://www.anthropic.com/engineering/writing-tools-for-agents) recommends evaluating realistic tasks, useful return context and errors, and response filtering/pagination. Its [advanced-tool-use article](https://www.anthropic.com/research/advanced-tool-use) demonstrates why deferred descriptions and selective intermediate results matter at scale. Those are provider-specific implementations, not evidence that either installed host exposes all of them. Keep any programmatic orchestration with the host; do not add a Mirket code-execution sandbox to emulate a provider feature. **Source-observed; performance benefit unmeasured.**

**Discriminating test:** a host given a missing-schema SQL error identifies the exact prerequisite and stops or obtains it through authorized host work. It must not repeatedly call the same failing operation, install a package implicitly, or silently substitute text matches for resolved references.

## Catalog recommendations and ideas to reject or defer

- **Retain the 52 approved references.** Add the ranked sources only after the user chooses them. Within authoring mappings, downgrade whole-workflow machinery to comparison-only and restricted text to link-only. Removing a source’s runtime influence is different from deleting the user’s selected reference.
- **Do not add another general agent framework.** Pi, Hermes, LangGraph and similar products offer useful ideas, but host-owned lifecycle is a deliberate advantage here. A Mirket implementation of their loops, compaction, spawners or provider APIs would violate the selected boundary.
- **Keep curated embedded memory.** QMD’s interfaces are a useful challenger for ergonomics, not evidence that its runtime replaces canonical temporal facts, correction and forgetting. Do not claim arbitrary graph reasoning from explicit relational links. Hindsight/Graphiti should be reconsidered only if a concrete required memory task fails and their complete costs/ownership fit is demonstrated.
- **No passive learning or automatic skill rewriting.** Hermes-style learning can improve procedural reuse, but automatic transcript capture, prompt injection and background skill updates are outside this plan. Host-curated source-backed notes and explicitly requested project skills provide the useful portion.
- **Do not ship agent-browser alongside Playwright by default.** Its current strategy emphasizes a Rust/CDP implementation and broader desktop/cloud integrations; those do not replace the selected three-engine browser contract. Borrow observation, ref-lifetime and versioned-help ideas only.
- **Do not adopt all of Microsoft’s or K-Dense’s catalogs.** The inspected M365 evaluator is specifically tied to deployed Copilot agents, tenant consent, Azure model configuration and a latest-package CLI invocation. Those assumptions are inappropriate for Mirket’s local guide test infrastructure. K-Dense’s statistical methods are relevant; a broad scientific environment is not implied.
- **Do not substitute source inspection or accessibility snapshots for execution evidence.** A license, a recent commit, a provider benchmark, a passing schema, a screenshot or a skill’s own quality claim establishes a narrower fact than end-to-end capability.
- **Do not build an autonomous crawler or new web-search provider to fill an unobserved gap.** The selected public browsing contract is adequate to begin; state-grounded interaction and attributable extraction matter first. Search-provider/account integration would require its own concrete user value and authorization.
- **Do not turn all suggestions into dependencies.** Property testing, accessibility checks and statistical methods can often use established project tools. A need for a production library must be justified separately; guidance approval is not dependency approval.
