## Focused source checks and qualification implications

**Native PHP.** The PHPantom `0.11.1` release API lists all three required native archives. Its tagged configuration makes project settings override global settings and watches both for changes; external diagnostics/formatters have autodetection and command overrides. Thus a private global configuration alone cannot establish the policy. The current plan correctly requires that project configuration cannot re-enable execution. Exercise startup, edit and configuration reload with useful cross-file navigation. These are existing M0b obligations, not a newly discovered omission. [Release metadata](https://api.github.com/repos/PHPantom-dev/phpantom_lsp/releases/tags/0.11.1), [tagged configuration](https://github.com/PHPantom-dev/phpantom_lsp/blob/0.11.1/docs/configuration.md).

The tagged build script embeds stubs at compile time but can successfully emit an empty index when stubs are absent/stale in offline mode or fetching fails. The existing requirement to prepare **complete** built-in stubs must be verified from the built candidate and a built-in-symbol fixture, not merely a successful offline build. No build script was run here. [Tagged build script](https://github.com/PHPantom-dev/phpantom_lsp/blob/0.11.1/build.rs). Phpactor's documented Windows route remains WSL, confirming that the old exception was appropriately removed. [Requirements](https://github.com/phpactor/phpactor/blob/master/README.md).

**Ruby.** The security documentation still describes ordinary workspace execution, bundle operations and add-on loading; the composed bundle deliberately includes project dependencies. A lockfile/private interpreter does not prove passive loading. The amended plan explicitly requires the missing supported route and preserves a product decision if useful navigation cannot coexist with the execution contract. There is no source basis here for calling Ruby qualified or for replacing it preemptively. [Trust model](https://shopify.github.io/ruby-lsp/security.html), [composition](https://shopify.github.io/ruby-lsp/composed-bundle.html).

**Extraction.** Tagged docling.rs `v2.51.1` source confirms the corrected renderer distinction: the conformance invocation uses `--skip-ocr` and `DOCLING_RS_RENDERER=docling-parse`, while ordinary default rendering is Rust and PDFium is a feature. Its release listing still lacks a Windows ARM64 archive; a native build is a qualification task, not an established benefit of choosing Rust. The amended all-target promotion condition covers that uncertainty. [Conformance method](https://github.com/docling-project/docling.rs/blob/v2.51.1/docs/PDF_CONFORMANCE.md), [CLI features](https://github.com/docling-project/docling.rs/blob/v2.51.1/crates/docling-cli/Cargo.toml), [release inventory](https://api.github.com/repos/docling-project/docling.rs/releases/tags/v2.51.1).

For the M0b comparison, identify renderer, OCR engine/languages, models and precision, font assets, execution provider and thread/page-worker settings in the experiment record. Compare the intended shipped configuration, not a conformance shim against a different production pipeline. Record any shim/native resources if actually selected. This is the concrete execution of the exact feature/model inventory and identical-outcome comparison already required at `planning/implementation-plan.md:100`, `:119` and `:124`; it does not require another planning subsystem. Keep the narrow Python pipeline as baseline until the challenger passes, and retain both Python ownership roles where PDF/SQL and UNO still need them.

**OpenPencil/HyperFrames.** Reinspection of the same tags confirms why the closure gate matters. OpenPencil CLI/core manifests include MCP, CanvasKit and export/Tauri-related dependencies. HyperFrames producer includes studio-server and Puppeteer dependencies; engine and producer declare different compatible Puppeteer ranges and Node 22+. Source exports/build scripts are not a substitute for inspecting published artifacts. These observations neither prove a desktop/studio service starts nor establish that such dependencies can be omitted. The revised plan makes the actual import/build/runtime decision in the first inventory and tests saved outputs. [OpenPencil CLI](https://github.com/open-pencil/open-pencil/blob/v0.16.0/packages/cli/package.json), [core](https://github.com/open-pencil/open-pencil/blob/v0.16.0/packages/core/package.json), [HyperFrames producer](https://github.com/heygen-com/hyperframes/blob/v0.8.192/packages/producer/package.json), [engine](https://github.com/heygen-com/hyperframes/blob/v0.8.192/packages/engine/package.json).
