# Visual and motion reference fidelity review (2026-10-27)

This review covers the 20 retained C/E references in `planning/references.md` at
their exact pinned revisions. It checks one or more decision-relevant sections
of each source, its license file, and the local skills that name it in
`skills/catalog.json`. Raw source bodies are retained outside the repository in
`/tmp/mirket-reference-raw-2026-10-27`; only hashes, section names, and
independent summaries are recorded here. No upstream material was adapted into
the shipped skills; the private raw downloads were not executed, and no source
asset, font, launcher, registry, MCP server, or runtime was admitted.

The source hashes below are SHA-256 of the fetched pinned source file; the
license hashes are SHA-256 of the fetched pinned license file. A source body
being reachable and MIT/Apache licensed does not make its branded assets,
fonts, examples, or runtime part of Mirket. `comparison-only` means the local
skill may use an independently authored technique; `link-only` means the
material must remain a locator because its terms or rights are not suitable for
adaptation.

## Cross-cutting corrections

The one demonstrated, actionable correction is attribution preservation:
`art-direction` and `vector-art` must retain creator/source/license/required
notices for an asset or component actually incorporated into the project. A
comparison reference, private download, or inspiration link does not grant a
right to ship its assets, fonts, examples, or brand material. The correction is
already applied by the owning skill changes; this review does not duplicate
that edit.

The following are deliberately recorded as optional refinements rather than
findings: source-specific viewport sets or timing thresholds; a mandatory
motion-gap category; a diagram pre-render complexity plan; a prescribed
intermediate-scroll screenshot cadence; and naming a particular CSS reduced
motion implementation. Existing local bodies already cover the underlying
responsive, lifecycle, reduced-motion, interior-scroll, and visual-evidence
requirements. None justified a new tool, a universal numeric gate, or a second
agent/orchestration route.

No new Mirket tool is justified. Browser inspection, live UI interaction,
document work, dependency installation, SQL, agent spawning and permissions
remain Codex/project-owned. Hallmark, Taste, Impeccable, Better Design, Canvas
UI and Remotion’s launchers/registries/MCP routes were deliberately excluded.
The source bodies are useful methods, not tool receipts or runtime admissions.

The exact local body owners should apply only the accepted attribution fix after
reviewing the evidence here; this disjoint report does not mutate shipped
skills. All reference mappings above are source-to-technique evidence, not
tool receipts or proof of runtime support.
